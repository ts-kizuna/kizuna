title: Mounting
description: Connect your router to the contract and serve it with an adapter.
---

`server.api` puts your [router](/docs/building/router) into the API object your framework adapter mounts. The `server` handle comes from `new KizunaServer(contract)`.

## `server.api`

```ts title="api.ts"
import { server } from './server'; // new KizunaServer(contract) from @ts-kizuna/express, fastify, hono, or next
import { router } from './router';
import { requireUser, requireMember } from './guards';

export const api = server.api({
    router,
    guards: {
        user: requireUser,
        member: requireMember,
    },
});
```

## Guards

If the contract declares identities, pass one guard per identity under `guards`. A guard verifies the extracted credential and returns the identity's context or a denial. The contract's auth map decides which routes it protects. See the [Authentication guide](/docs/authentication).

## Request context

For request-scoped values every handler needs (analytics ids, a logger, a tenant), declare them with [`Kizuna.requestContext`](/docs/reference/kizuna-request-context), register them on `new Kizuna()`, and resolve each with `server.requestContext`. Resolvers run on every route, never deny, and handlers receive their values typed under each name.

## Scheduled jobs

If the contract declares [scheduled jobs](/docs/jobs), write their handlers with `server.jobs` and pass them to `server.api` next to the router:

```ts title="api.ts"
export const api = server.api({
    router,
    jobs: jobHandlers,
    guards: {
        scheduler: requireScheduler,
    },
});
```

`api.mount` then serves the two [job endpoints](/docs/jobs#the-two-job-endpoints), and every handler receives a typed `jobs` runner so a route can run one in process.

## Plugins

If the contract declares [plugins](/docs/plugins), pass their server halves under `plugins`:

```ts title="api.ts"
import { mcpPluginServer } from '@ts-kizuna/mcp/server';
import { openApiPluginServer } from '@ts-kizuna/openapi/server';

export const api = server.api({
    router,
    plugins: {
        mcp: mcpPluginServer(),
        openApi: openApiPluginServer(),
    },
});
```

Whatever a plugin exports then arrives on every handler under `plugins`, keyed by name.

## Middleware

Rate limiting, multipart parsing, and the rest go in your framework's own middleware (`app.use`, Fastify hooks). Authentication belongs in guards, request-scoped values in `requestContext`.

## Mounting

Once you have an `api` object, mount it with the adapter's mount verb:

**Express:**

```ts title="src/index.ts"
import express from 'express';
import { api } from './server/api';

const app = express();
app.use(express.json());
api.mount(app);
app.listen(3000);
```

**Fastify:**

```ts title="src/index.ts"
import Fastify from 'fastify';
import { api } from './server/api';

const app = Fastify();
await api.mount(app);
app.listen({
    port: 3000,
});
```

**Hono:**

```ts title="src/index.ts"
import { Hono } from 'hono';
import { api } from './server/api';

const app = new Hono();
api.mount(app);

export default app;
```

**Next.js:**

```ts title="src/app/api/[...ts-kizuna]/route.ts"
import { api } from '@/server/api';

export const { GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS } = api.mount({
    basePath: '/api',
});
```
