title: Contract
description: Define the routes shared between your server and client.

The contract is a plain TypeScript object that describes every route in your API — methods, paths, Zod schemas for inputs and outputs. Both your server and client import it.

## `createContract`

```ts
import { createContract } from '@ts-kizuna/core';
import { ProblemDetailsSchema } from '@ts-kizuna/core/schemas';
import { z } from 'zod';

export const UserSchema = z
    .object({
        id: z.string(),
        name: z.string(),
        email: z.email(),
    })
    .meta({
        id: 'User',
    });

export const contract = createContract({
    listUsers: {
        method: 'GET',
        path: '/users',
        query: z.object({
            page: z.number().int().min(1).default(1),
            limit: z.number().int().min(1).max(100).default(10),
        }),
        responses: {
            200: z.object({
                users: z.array(UserSchema),
                total: z.number(),
            }),
        },
    },
    createUser: {
        method: 'POST',
        path: '/users',
        body: z.object({
            name: z.string().min(1),
            email: z.email(),
        }),
        responses: {
            201: UserSchema,
            400: ProblemDetailsSchema,
        },
    },
    getUser: {
        method: 'GET',
        path: '/users/:id',
        responses: {
            200: UserSchema,
            404: ProblemDetailsSchema,
        },
    },
});
```

## Route fields

| Field         | Required | Description                                                                                    |
| ------------- | -------- | ---------------------------------------------------------------------------------------------- |
| `method`      | Yes      | `GET` `POST` `PUT` `PATCH` `DELETE` `HEAD` `OPTIONS`                                           |
| `path`        | Yes      | URL path — use `:name` for path parameters                                                     |
| `body`        | —        | Request body schema                                                                            |
| `query`       | —        | Query string schema                                                                            |
| `headers`     | —        | Request headers schema                                                                         |
| `responses`   | Yes      | Response schemas keyed by status code                                                          |
| `contentType` | —        | `'application/json'` (default), `'multipart/form-data'`, `'application/x-www-form-urlencoded'` |
| `summary`     | —        | Short description shown in OpenAPI                                                             |
| `tags`        | —        | OpenAPI tags                                                                                   |

## Query, path, and header coercion

Values in the URL and in headers always arrive as strings. ts-kizuna coerces them to the types you declare, so you write the schema you actually mean and get the parsed value on both the client and the server:

| Declare                  | Accepts on the wire  | You get             |
| ------------------------ | -------------------- | ------------------- |
| `z.number()` / `z.int()` | `"42"`               | `42`                |
| `z.boolean()`            | `"true"` / `"false"` | `true` / `false`    |
| `z.bigint()`             | `"9007199254740993"` | `9007199254740993n` |
| `z.date()`               | an ISO 8601 string   | `Date`              |

Arrays of these coerce too (`z.array(z.number())`). The fetch client serializes `Date` and `bigint` values for you, so a `z.date()` query param round-trips without any manual formatting. Request bodies are sent as JSON and keep their types, so they are never coerced.

Because coercion is built in, **`z.coerce` is not supported** — `createContract` throws if any schema uses it. Use the plain schema (`z.number()`, `z.date()`, `z.bigint()`) instead. When you genuinely want to receive a different type than you send, `z.string().transform(...)` is the explicit, type-safe way to do it.

## Response schemas

Simple form — a Zod schema per status code:

```ts
responses: {
    200: UserSchema,
    404: ProblemDetailsSchema,
},
```

With typed response headers:

```ts
responses: {
    200: {
        body: UserSchema,
        headers: z.object({
            'x-request-id': z.string().optional(),
        }),
    },
    404: ProblemDetailsSchema,
},
```

No-content responses — use `z.void()` when a status code carries no body:

```ts
responses: {
    204: z.void(),
    404: ProblemDetailsSchema,
},
```

Non-JSON responses — set `contentType` to send the body as-is instead of JSON. Responses default to `application/json` (errors to `application/problem+json`); declare a non-JSON body as `z.string()`:

```ts
responses: {
    200: {
        body: z.string(),
        contentType: 'text/csv',
    },
},
```

Binary responses — use [`BinarySchema`](/docs/reference/binary-and-file-schemas) for a body of raw bytes (`Uint8Array`/`Buffer`), e.g. a PDF download:

```ts
import { BinarySchema } from '@ts-kizuna/core/schemas';

responses: {
    200: {
        body: BinarySchema,
        contentType: 'application/pdf',
    },
},
```

## Models

Use [`createModel`](/docs/reference/create-model) to give a Zod schema a name that the OpenAPI and Swift generators pick up.

```ts
import { createModel } from '@ts-kizuna/core';

export const UserSchema = createModel({
    title: 'User',
    description: 'A user in the system',
    schema: z.object({
        id: z.string(),
        name: z.string(),
        email: z.email(),
    }),
});
```

Without a title, the generators inline the schema everywhere it appears. With `createModel`:

- **OpenAPI** — the schema is extracted into `components.schemas.User` and every usage becomes a `$ref: '#/components/schemas/User'` reference
- **Swift** — the schema becomes a named `public struct User` in the generated client, shared across all routes that reference it
- **TypeScript** — export a type alongside the schema with `export type User = z.infer<typeof UserSchema>` (see [Exporting types from schemas](#exporting-types-from-schemas))

## Nested contracts

Split your contract across files using sub-contracts. Use [`createTag`](/docs/reference/create-tag) to name and describe each group:

```ts
// contracts/tags.ts
import { createTag } from '@ts-kizuna/core';

export const Users = createTag({
    title: 'Users',
    description: 'User management endpoints',
});

export const Health = createTag({
    title: 'Health',
    description: 'Service health and uptime monitoring',
});
```

```ts
// contracts/users.ts
import { createContract } from '@ts-kizuna/core';
import { Users } from './tags';

export const usersContract = createContract(Users, {
    listUsers: { ... },
    createUser: { ... },
});
```

```ts
// contract.ts
export const contract = createContract({
    users: usersContract,
    health: healthContract,
});
```

The tag's `title` becomes the OpenAPI tag for all routes in that sub-contract. The optional `description` is included in the OpenAPI tag definition.

Routes can also reference tags directly for cross-tagging:

```ts
import { Users, Health } from './tags';

cancelAccount: {
    method: 'POST',
    path: '/account/cancel',
    tags: [Users, Health],
    ...
},
```

## Deprecating routes and fields

To deprecate a route or a response field, add a `/** @deprecated */` JSDoc tag directly above it. You can optionally include a migration message: `/** @deprecated use createUser instead */`.

**Route:**

```ts
/**
 * @deprecated
 */
deleteUser: {
    method: 'DELETE',
    path: '/users/:id',
    responses: {
        200: z.object({
            success: z.boolean(),
        }),
    },
},
```

**Field:**

```ts
getUser: {
    method: 'GET',
    path: '/users/:id',
    responses: {
        200: z.object({
            id: z.string(),
            name: z.string(),
            /**
             * @deprecated
             */
            legacyUsername: z.string().optional(),
        }),
    },
},
```

IDEs show a strikethrough on deprecated routes and fields right away. To carry the tags into the OpenAPI spec and Swift client, add the one-time build step in [Deprecations](/docs/deprecations).

## Exporting types from schemas

Create a separate `types.ts` file that imports your schemas and exports inferred types. This keeps schemas and types cleanly separated:

```ts
// packages/contract/src/types.ts
import type { z } from 'zod';
import { UserSchema, CreateUserSchema } from './contract';

export type User = z.infer<typeof UserSchema>;
export type CreateUserInput = z.infer<typeof CreateUserSchema>;
```

Consumers import the types directly:

```ts
import type { User } from '@shared/contract/types';

function UserCard({ user }: { user: User }) {
    return <div>{user.name}</div>;
}
```
