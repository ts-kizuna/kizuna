`@ts-kizuna/next` connects a ts-kizuna API to a Next.js App Router application via a single catch-all route file.

**Requires Next.js ≥ 16** (App Router).

<InstallTabs packageName="@ts-kizuna/next" />

## Setup

Wrap your `next.config.ts` with `withKizuna`:

```ts title="next.config.ts"
import type { NextConfig } from 'next';
import { withKizuna } from '@ts-kizuna/next/config';

const nextConfig: NextConfig = {
    // your config
};

export default withKizuna(nextConfig);
```

Then create a catch-all route at `src/app/api/[...ts-kizuna]/route.ts`. The adapter exports handlers for every HTTP method, which Next.js dispatches automatically.

```ts title="src/lib/router.ts"
import { createRouter } from '@ts-kizuna/next';
import { contract } from '@shared/contract';

export const router = createRouter(contract, {
    users: {
        listUsers: async ({ query }) => {
            const found = await db.users.findMany({
                skip: (query.page - 1) * query.limit,
                take: query.limit,
            });
            return {
                status: 200,
                body: {
                    users: found,
                    total: await db.users.count(),
                },
            };
        },
        createUser: async ({ body }) => {
            const user = await db.users.create(body);
            return {
                status: 201,
                body: user,
            };
        },
        getUser: async ({ params }) => {
            const user = await db.users.findById(params.id);
            if (!user) {
                return {
                    status: 404,
                    body: {
                        detail: 'Not found',
                    },
                };
            }
            return {
                status: 200,
                body: user,
            };
        },
    },
});
```

```ts title="src/lib/server.ts"
import { createApi } from '@ts-kizuna/next';
import { contract } from '@shared/contract';
import { router } from './router';

export const api = createApi({
    contract,
    router,
});
```

```ts title="src/app/api/[...ts-kizuna]/route.ts"
import { createNextEndpoints } from '@ts-kizuna/next';
import { api } from '../../../lib/server';

export const { GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS } = createNextEndpoints(api, {
    basePath: '/api',
});
```

`api.mount({ basePath: '/api' })` is a convenience method that calls `endpoints` internally — use whichever you prefer.

The `basePath` option tells the adapter to strip the prefix when matching requests against the declared paths.

## Handler context

Each handler receives `{ params, query, body, headers, request }`. The `request` is the native `NextRequest` — useful when you need to read cookies or access other request properties.

```ts
getUser: async ({ params, request }) => {
    const token = request.cookies.get('session')?.value;
    const user = await db.users.findById(params.id);
    return {
        status: 200,
        body: user,
    };
},
```

## Middleware

Per-route middleware runs before the handler. Declare which routes it runs on with a `middleware` map on `createApi`, shaped like your routes. Authentication is just middleware that attaches data to `request`, which handlers then read.

### Writing a guard

A guard is the common case: a middleware that allows or rejects a request. `guard` wraps that check so you skip the `new Response()` boilerplate — call `deny(status, detail)` to reject, return to allow. The second argument is the matched `route` (its `path`, `method`, and `params`), handy for per-route decisions in a shared guard.

```ts title="src/lib/guards.ts"
import { guard } from '@ts-kizuna/next';

export const authenticate = guard(async (request, _route, deny) => {
    const session = await getSession(request);
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    request.userId = session.userId;
});

export const requireAdmin = guard((request, _route, deny) => {
    if (request.userRole !== 'admin') {
        return deny(403, 'Forbidden');
    }
});

export const requireMembership = guard(async (request, route, deny) => {
    const membership = await checkMembership(request.userId, route.params?.id);
    if (!membership) {
        return deny(403, 'Forbidden');
    }
    request.member = membership;
});
```

### Wiring middleware to routes

The map mirrors your routes. Every top-level group key must be present — use `[]` for public groups.

```ts title="src/lib/middleware.ts"
import { createMiddleware } from '@ts-kizuna/next';
import { contract } from '@shared/contract';
import { authenticate, requireAdmin, requireMembership } from './guards';

export const middleware = createMiddleware(contract, {
    // Group-level: applies to all routes under "users"
    users: [authenticate],
    // Group default with per-route override
    members: {
        '*': [authenticate, requireMembership],
        listMembers: [authenticate],
    },
    // Multiple middleware compose left to right
    admin: [authenticate, requireAdmin],
    // Explicit public group
    health: [],
});
```

### Plugging into the API

```ts title="src/lib/server.ts"
import { createApi } from '@ts-kizuna/next';

export const api = createApi({
    contract,
    router,
    middleware,
});
```

Properties set on `request` by guards are accessible in handlers via `{ request }`.

## Options

Pass options to `endpoints` (or `api.mount`):

```ts
createNextEndpoints(api, {
    basePath: '/api',
    responseValidation: false,
});
```

| Option               | Default | Description                                                                                                                                                  |
| -------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `basePath`           | `''`    | Path prefix to strip when matching incoming paths                                                                                                            |
| `requestMiddleware`  | `[]`    | **Deprecated.** Use the `middleware` map via `createApi` instead.                                                                                            |
| `responseValidation` | `false` | Validate handler return values against response schemas. Enable in development.                                                                              |
| `onError`            | —       | Map a thrown error into a response (inbound migration seam); return an `AdapterResult`/`Response` to override the default 500. Also settable on `createApi`. |

## `onError`

Set `onError` on `createApi` (or pass it to `endpoints`) to send a custom response instead of the default 500:

```ts title="src/lib/server.ts"
import { createApi } from '@ts-kizuna/next';
import { contract } from '@shared/contract';
import { router } from './router';

export const api = createApi({
    contract,
    router,
    onError: (error) => {
        if (error instanceof AuthError) {
            return {
                kind: 'raw-response',
                response: new Response(
                    JSON.stringify({
                        message: 'Unauthorized',
                    }),
                    {
                        status: 401,
                        headers: {
                            'Content-Type': 'application/json',
                        },
                    }
                ),
            };
        }
    },
});
```

Returning `undefined` lets the default 500 flow run.

## `requestMiddleware` (deprecated)

> Use [`middleware`](#middleware) instead. `requestMiddleware` applies globally to all routes; `middleware` lets you declare per-route and per-group middleware that mirrors your routes.

`requestMiddleware` applies a flat array of middleware to every matched route. It still works alongside `middleware` — global middleware runs after per-route middleware.

## Type-safe request properties

If your middleware sets custom properties on the request, use module augmentation to extend `NextRequest` so handlers can access them without casts:

```ts title="types/next.d.ts"
import 'next/server';

declare module 'next/server' {
    interface NextRequest {
        userId: string;
        sessionId?: string | null;
    }
}
```

With the augmentation in place, both middleware and handlers are fully typed:

```ts
requestMiddleware: [
    async (request) => {
        const session = await getSession(request);
        if (!session) {
            return new Response(null, {
                status: 401,
            });
        }
        request.userId = session.userId;
        request.sessionId = session.id;
    },
],
```

```ts
getUser: async ({ params, request }) => {
    console.log(request.userId);
    // ...
},
```

## Multipart / file uploads

Routes with `contentType: 'multipart/form-data'` work natively. The adapter calls `request.formData()` internally — no additional middleware needed.

```ts
uploadAvatar: async ({ body }) => {
    // body.file is a File, body.userId is a string
    await storage.upload(body.userId, body.file);
    return {
        status: 200,
        body: {
            size: body.file.size,
            userId: body.userId,
        },
    };
},
```
