`@ts-kizuna/next` connects a ts-kizuna contract to a Next.js App Router application via a single catch-all route file.

**Requires Next.js ≥ 16** (App Router).

<InstallTabs packageName="@ts-kizuna/next" />

## Setup

Create a catch-all route at `src/app/api/[...ts-kizuna]/route.ts`. The adapter exports handlers for every HTTP method, which Next.js dispatches automatically.

```ts
// src/lib/router.ts
import { createRouter } from '@ts-kizuna/next';
import { contract } from '@shared/contract';

export const router = createRouter(contract, {
    listUsers: async ({ query }) => {
        const users = await db.users.findMany({
            skip: (query.page - 1) * query.limit,
            take: query.limit,
        });
        return {
            status: 200,
            body: {
                users,
                total: await db.users.count(),
            },
        };
    },
    createUser: async ({ body }) => {
        const user = await db.users.create(body);
        return {
            status: 201,
            body: user,
        };
    },
    getUser: async ({ params }) => {
        const user = await db.users.findById(params.id);
        if (!user) {
            return {
                status: 404,
                body: {
                    message: 'Not found',
                },
            };
        }
        return {
            status: 200,
            body: user,
        };
    },
});
```

```ts
// src/lib/server.ts
import { createApi } from '@ts-kizuna/next';
import { contract } from '@shared/contract';
import { router } from './router';

export const api = createApi({
    contract,
    router,
});
```

```ts
// src/app/api/[...ts-kizuna]/route.ts
import { createNextEndpoints } from '@ts-kizuna/next';
import { api } from '../../../lib/server';

export const { GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS } = createNextEndpoints(api, {
    basePath: '/api',
});
```

The `basePath` option tells the adapter to strip the prefix when matching routes against the contract paths.

## Handler context

Each handler receives `{ params, query, body, headers, request }`. The `request` is the native `NextRequest` — useful when you need to read cookies or access other request properties.

```ts
getUser: async ({ params, request }) => {
    const token = request.cookies.get('session')?.value;
    const user = await db.users.findById(params.id);
    return {
        status: 200,
        body: user,
    };
},
```

## Middleware and guards

Use `createGuard` to define access checks and `createMiddleware` to wire them to routes.

### Defining guards

`createGuard` creates a middleware that checks access before the handler runs. Call `deny` to reject, return normally to allow. No manual `new Response()` boilerplate.

```ts
// src/lib/guards.ts
import { createGuard } from '@ts-kizuna/next';

export const authenticate = createGuard(async (request, route, deny) => {
    const session = await getSession(request);
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    request.userId = session.userId;
});

export const requireAdmin = createGuard(async (request, route, deny) => {
    if (request.userRole !== 'admin') {
        return deny(403, 'Forbidden');
    }
});

export const requireMembership = createGuard(async (request, route, deny) => {
    const locationId = route.params?.id;
    if (!locationId) {
        return deny(400, 'Missing location ID');
    }

    const location = await resolveLocation(locationId);
    if (!location) {
        return deny(404, 'Location not found');
    }

    const membership = await checkMembership(request.userId, location.organizationId);
    if (!membership) {
        return deny(403, 'Forbidden');
    }

    request.location = location;
    request.member = membership;
});
```

### Wiring guards to routes

```ts
// src/lib/middleware.ts
import { createMiddleware } from '@ts-kizuna/next';
import { contract } from '@shared/contract';
import { authenticate, requireAdmin, requireMembership } from './guards';

export const middleware = createMiddleware(contract, {
    // Group-level: applies to all routes under "users"
    users: [authenticate],
    // Group default with per-route override
    billing: {
        '*': [authenticate],
        webhook: [],
    },
    // Multiple guards compose left to right
    admin: [authenticate, requireAdmin],
    // Individual route
    locationOrders: [authenticate, requireMembership],
    // Explicit public route
    health: [],
});
```

### Plugging into the API

```ts
import { createApi } from '@ts-kizuna/next';

export const api = createApi({
    contract,
    router,
    middleware,
});
```

Properties set on `request` by guards are accessible in handlers via `{ request }`.

## Options

```ts
createNextEndpoints(api, {
    basePath: '/api',
    responseValidation: false,
    onError: undefined,
});
```

| Option               | Default | Description                                                                                          |
| -------------------- | ------- | ---------------------------------------------------------------------------------------------------- |
| `basePath`           | `''`    | Path prefix to strip when matching contract routes                                                   |
| `requestMiddleware`  | `[]`    | **Deprecated.** Use `middleware` via `createApi` instead.                                            |
| `responseValidation` | `false` | Validate handler return values against response schemas. Enable in development.                      |
| `onError`            | —       | Custom handler for unhandled errors. Return an `AdapterResult` to override the default 500 response. |

## `onError`

Return an `AdapterResult` from `onError` to send a custom response instead of the default 500:

```ts
// src/lib/server.ts
import { createApi } from '@ts-kizuna/next';
import { contract } from '@shared/contract';
import { router } from './router';

export const api = createApi({
    contract,
    router,
    onError: (error) => {
        if (error instanceof AuthError) {
            return {
                kind: 'raw-response',
                response: new Response(
                    JSON.stringify({
                        message: 'Unauthorized',
                    }),
                    {
                        status: 401,
                        headers: {
                            'Content-Type': 'application/json',
                        },
                    }
                ),
            };
        }
    },
});
```

Returning `undefined` lets the default 500 flow run.

## `requestMiddleware` (deprecated)

> Use [`middleware`](#middleware) instead. `requestMiddleware` applies globally to all routes; `middleware` lets you declare per-route and per-group middleware that mirrors the contract shape.

`requestMiddleware` applies a flat array of middleware to every matched route. It still works alongside `middleware` — global middleware runs after per-route middleware.

## Type-safe request properties

If your middleware sets custom properties on the request, use module augmentation to extend `NextRequest` so handlers can access them without casts:

```ts
// types/next.d.ts
import 'next/server';

declare module 'next/server' {
    interface NextRequest {
        userId: string;
        sessionId?: string | null;
    }
}
```

With the augmentation in place, both middleware and handlers are fully typed:

```ts
requestMiddleware: [
    async (request) => {
        const session = await getSession(request);
        if (!session) {
            return new Response(null, {
                status: 401,
            });
        }
        request.userId = session.userId;
        request.sessionId = session.id;
    },
],
```

```ts
getUser: async ({ params, request }) => {
    console.log(request.userId);
    // ...
},
```

## Multipart / file uploads

Routes with `contentType: 'multipart/form-data'` work natively. The adapter calls `request.formData()` internally — no additional middleware needed.

```ts
uploadAvatar: async ({ body }) => {
    // body.file is a File, body.userId is a string
    await storage.upload(body.userId, body.file);
    return {
        status: 200,
        body: {
            size: body.file.size,
            userId: body.userId,
        },
    };
},
```

## Server Actions

`createServerAction` turns a typed client method into a React Server Action. You use it **exactly like the client**: call it with the route's arguments, get back the same `{ status, body }` response, and narrow on `status`. The action runs server-side, strips the inputs a caller shouldn't supply (anything `inject` fills), and `onSuccess` is where you revalidate or redirect.

```ts
// src/lib/api-client.ts
import { createClient } from '@ts-kizuna/fetch';
import { contract } from '@shared/contract';

export const client = createClient(contract, {
    baseUrl: process.env.API_URL!,
});
```

```ts
// src/app/users/actions.ts
'use server';
import { revalidatePath } from 'next/cache';
import { createServerAction } from '@ts-kizuna/next';
import { client } from '@/lib/api-client';

export const createUser = createServerAction(client.users.createUser, {
    onSuccess: () => {
        revalidatePath('/users');
    },
});

export const deleteUser = createServerAction(client.users.deleteUser, {
    onSuccess: () => {
        revalidatePath('/users');
    },
});
```

Call it and narrow on `status` — just like the client:

```ts
const result = await createUser({
    body: {
        name: 'Ada',
        email: 'ada@example.com',
    },
});

if (result.status === 201) {
    result.body.id; // typed success body
} else if (result.status === 400) {
    result.body.errors; // validation issues, typed
}
```

### What it returns

The action returns the client method's response **unchanged** — the same `{ status, body }` discriminated union (with headers). Narrow on `status` to get the body for that response; multiple success statuses (e.g. `200` and `201`) each keep their own typed body.

A genuine transport failure (the API is unreachable) throws — handle it with a `try/catch` or a Next.js error boundary.

### Field-level validation errors

For a `400`, `result.body` is kizuna's `ValidationError` — each entry in `errors` carries the failing field's `path`. Render each message above its input:

```tsx
'use client';
import { useState, useTransition } from 'react';
import { createUser } from './actions';

export function AddUserForm() {
    const [name, setName] = useState('');
    const [email, setEmail] = useState('');
    const [errors, setErrors] = useState<Record<string, string>>({});
    const [pending, startTransition] = useTransition();

    function addUser() {
        startTransition(async () => {
            const result = await createUser({ body: { name, email } });
            if (result.status === 201) {
                setErrors({});
                return;
            }
            if (result.status === 400) {
                setErrors(Object.fromEntries(result.body.errors.map((issue) => [issue.path[0], issue.message])));
            }
        });
    }

    return (
        <div>
            <label>
                Name
                {errors.name && <span>{errors.name}</span>}
                <input value={name} onChange={(event) => setName(event.target.value)} />
            </label>
            <label>
                Email
                {errors.email && <span>{errors.email}</span>}
                <input value={email} onChange={(event) => setEmail(event.target.value)} />
            </label>
            <button onClick={addUser} disabled={pending}>
                Add user
            </button>
        </div>
    );
}
```

When a route declares its **own** `400` as well, `status === 400` carries both shapes — the custom error _and_ validation. There, [`isValidationError`](/docs/reference/is-validation-error) (re-exported from `@ts-kizuna/next`) narrows `result.body` to just the validation shape:

```ts
if (result.status === 400 && isValidationError(result.body)) {
    result.body.errors;
}
```

### Options

| Option      | Default | Description                                                                                                            |
| ----------- | ------- | ---------------------------------------------------------------------------------------------------------------------- |
| `inject`    | —       | Supply server-derived parts of the request (e.g. an owner id). Merged in and **removed from the caller's input type**. |
| `onSuccess` | —       | Run after a 2xx response — revalidate, redirect, or other side effects; receives the success response.                 |

### Injecting server-derived fields

Use `inject` for values that must come from the server, not the client — an owner id, a tenant id. The returned fields are deep-merged into the request and **removed from the action's argument type**, so the caller can't pass (or forge) them:

```ts
export const createPost = createServerAction(client.posts.createPost, {
    inject: async () => ({
        body: {
            authorId: await currentUserId(),
        },
    }),
});
```

```ts
// the caller only knows about `title`; `authorId` is filled server-side
await createPost({
    body: {
        title,
    },
});
```

### Authentication

Attach credentials in the client's `onRequest` — it runs per request, so you can read cookies server-side:

```ts
import { cookies } from 'next/headers';

export const client = createClient(contract, {
    baseUrl: process.env.API_URL!,
    onRequest: async ({ headers }) => {
        headers.set('cookie', (await cookies()).toString());
    },
});
```
