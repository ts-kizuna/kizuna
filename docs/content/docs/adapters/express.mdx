`@ts-kizuna/express` connects a ts-kizuna contract to an Express 5 application. It handles routing, request validation, body parsing, and error formatting — all driven by your contract schema.

**Requires Express ≥ 5.**

<InstallTabs packageName="@ts-kizuna/express express" />

## Setup

The standard setup uses three functions:

- `createRouter` — bind typed implementations to a contract
- `createApi` — combine a contract and its handlers into an API object
- `createExpressEndpoints` — mount the API on an Express app

```ts
// src/lib/router.ts
import { createRouter } from '@ts-kizuna/express';
import { contract } from '@shared/contract';

export const router = createRouter(contract, {
    listUsers: async ({ query }) => {
        const users = await db.users.findMany({
            skip: (query.page - 1) * query.limit,
            take: query.limit,
        });
        return {
            status: 200,
            body: {
                users,
                total: await db.users.count(),
            },
        };
    },
    createUser: async ({ body }) => {
        const user = await db.users.create(body);
        return {
            status: 201,
            body: user,
        };
    },
    getUser: async ({ params }) => {
        const user = await db.users.findById(params.id);
        if (!user) {
            return {
                status: 404,
                body: {
                    message: 'Not found',
                },
            };
        }
        return {
            status: 200,
            body: user,
        };
    },
});
```

```ts
// src/lib/server.ts
import { createApi } from '@ts-kizuna/express';
import { contract } from '@shared/contract';
import { router } from './router';

export const api = createApi({
    contract,
    router,
});
```

```ts
// src/index.ts
import express from 'express';
import { createExpressEndpoints } from '@ts-kizuna/express';
import { api } from './lib/server';

const app = express();
app.use(express.json());

createExpressEndpoints(api, app);

app.listen(3000);
```

## Handler context

Each handler receives `{ params, query, body, headers, req, res }`. The `req` and `res` are the native Express objects — useful when you need to access cookies, set custom headers, or stream a response.

```ts
getUser: async ({ params, req, res }) => {
    console.log(req.ip);
    res.setHeader('x-custom', 'value');
    const user = await db.users.findById(params.id);
    return {
        status: 200,
        body: user,
    };
},
```

## Middleware and guards

Use `createGuard` to define access checks and `createMiddleware` to wire them to routes.

### Defining guards

`createGuard` creates a middleware that checks access before the handler runs. Call `deny` to reject, return normally to allow. No `next()`, no `res.json()` boilerplate.

```ts
// src/lib/guards.ts
import { createGuard } from '@ts-kizuna/express';

export const authenticate = createGuard(async (req, res, deny) => {
    const session = getSession(req);
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    req.userId = session.userId;
});

export const requireAdmin = createGuard(async (req, res, deny) => {
    if (req.userRole !== 'admin') {
        return deny(403, 'Forbidden');
    }
});

export const requireMembership = createGuard(async (req, res, deny) => {
    const locationId = req.params.id;
    if (!locationId) {
        return deny(400, 'Missing location ID');
    }

    const location = await resolveLocation(locationId);
    if (!location) {
        return deny(404, 'Location not found');
    }

    const membership = await checkMembership(req.userId, location.organizationId);
    if (!membership) {
        return deny(403, 'Forbidden');
    }

    req.location = location;
    req.member = membership;
});
```

### Wiring guards to routes

```ts
// src/lib/middleware.ts
import { createMiddleware } from '@ts-kizuna/express';
import { contract } from '@shared/contract';
import { authenticate, requireAdmin, requireMembership } from './guards';

export const middleware = createMiddleware(contract, {
    // Group-level: applies to all routes under "users"
    users: [authenticate],
    // Group default with per-route override
    billing: {
        '*': [authenticate],
        webhook: [],
    },
    // Multiple guards compose left to right
    admin: [authenticate, requireAdmin],
    // Individual route
    locationOrders: [authenticate, requireMembership],
    // Omitted keys have no middleware (public routes)
});
```

### Plugging into the API

```ts
import { createApi } from '@ts-kizuna/express';

export const api = createApi({
    contract,
    router,
    middleware,
});
```

## Options

```ts
createExpressEndpoints(api, app, {
    responseValidation: false,
});
```

| Option               | Default | Description                                                                                                   |
| -------------------- | ------- | ------------------------------------------------------------------------------------------------------------- |
| `responseValidation` | `false` | Validate handler return values against response schemas — surfaces as 500 on mismatch. Enable in development. |
| `globalMiddleware`   | `[]`    | **Deprecated.** Use `middleware` via `createApi` instead.                                                     |

## Type-safe request properties

If your middleware sets custom properties on `req`, use declaration merging to extend the Express `Request` interface:

```ts
// types/express.d.ts
declare global {
    namespace Express {
        interface Request {
            userId: string;
            sessionId?: string | null;
        }
    }
}
```

With the augmentation in place, both middleware and handlers are fully typed:

```ts
getUser: async ({ params, req }) => {
    console.log(req.userId);
    // ...
},
```

## Method mismatches

If a path is matched but the method is not defined in the contract, the adapter returns 405 with an `Allow` header listing the supported methods. This follows [RFC 9110 §15.5.6](https://www.rfc-editor.org/rfc/rfc9110#section-15.5.6).

## Multipart / file uploads

For routes with `contentType: 'multipart/form-data'`, add a multipart middleware such as `multer` or `busboy` before the ts-kizuna handler. The adapter reads `req.body` as-is and does not parse multipart itself.

```ts
import multer from 'multer';

const upload = multer({
    storage: multer.memoryStorage(),
});

app.post('/avatar', upload.single('file'), (req, res, next) => {
    next();
});

createExpressEndpoints(api, app);
```
