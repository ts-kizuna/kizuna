`@ts-kizuna/mcp` adds a [Model Context Protocol](https://modelcontextprotocol.io) endpoint to your existing app. Each route becomes an MCP tool that AI assistants can discover and call. Works with Express, Fastify, Hono, and Next.js.

<InstallTabs packageName="@ts-kizuna/mcp" />

## Express

```ts title="src/index.ts"
import express from 'express';
import { createExpressEndpoints } from '@ts-kizuna/express';
import { createMcpEndpoint } from '@ts-kizuna/mcp/express';
import { api } from './lib/api';

const app = express();
app.use(express.json());

createExpressEndpoints(api, app);
createMcpEndpoint(api, app);

app.listen(3000);
```

`createMcpEndpoint` mounts the MCP protocol handler at `/mcp` by default. Change it with the `path` option.

## Fastify

```ts title="src/index.ts"
import Fastify from 'fastify';
import { fastifyKizuna } from '@ts-kizuna/fastify';
import { fastifyKizunaMcp } from '@ts-kizuna/mcp/fastify';
import { api } from './lib/api';

const app = Fastify();

app.register(fastifyKizuna, {
    api,
});
app.register(fastifyKizunaMcp, {
    api,
});

app.listen({
    port: 3000,
});
```

Mounts at `/mcp` by default, configurable with the `path` option.

## Hono

```ts title="src/index.ts"
import { Hono } from 'hono';
import { createHonoEndpoints } from '@ts-kizuna/hono';
import { createMcpEndpoint } from '@ts-kizuna/mcp/hono';
import { api } from './lib/api';

const app = new Hono();

createHonoEndpoints(api, app);
createMcpEndpoint(api, app);

export default app;
```

Same as Express — mounts at `/mcp` by default, configurable with the `path` option.

## Next.js

```ts title="app/mcp/route.ts"
import { createMcpEndpoint } from '@ts-kizuna/mcp/next';
import { api } from '../../lib/api';

export const { GET, POST, DELETE } = createMcpEndpoint(api);
```

Returns `{ GET, POST, DELETE }` — the three HTTP methods the MCP Streamable HTTP transport requires.

## How it works

Each route becomes an MCP tool:

- **Tool name** — the dotted route key from the routes (e.g. `users.getUser`)
- **Tool description** — from the route's `summary` and `description`, falling back to `METHOD /path`
- **Tool input** — structured as `{ params, query, body }` matching the route's schemas
- **Tool execution** — invokes the corresponding handler directly and returns `{ status, body }`

Routes with `contentType: 'multipart/form-data'` or `'application/x-www-form-urlencoded'` are excluded by default since MCP tools receive JSON. [Streaming routes](/docs/streaming) are excluded too, since a tool call returns a single result.

## Framework context

Handlers called via MCP receive the same framework context as regular HTTP handlers. The MCP endpoint passes its incoming request through automatically:

- **Express** — handlers receive `req` and `res`
- **Fastify** — handlers receive `request` and `reply`
- **Hono** — handlers receive `c` (Hono Context)
- **Next.js** — handlers receive `request`

## Auth

Secured tools authenticate via the headers of the MCP transport request. When an assistant calls one, the endpoint runs the [guards](/docs/auth) registered on `server.api`, exactly like the HTTP pipeline: each identity's credential is extracted from the headers, the guard verifies it, access gates apply, and the handler receives its typed identity context as usual. Nothing extra to wire — mounting a secured API gives you a secured MCP endpoint.

Configure the MCP client to send the credential as a header on the connection. For example, with Claude Code:

```sh
claude mcp add --transport http my-api http://localhost:3000/mcp --header "Authorization: Bearer <token>"
```

For an `apiKey` identity, send the header the identity names (e.g. `x-workspace-token`) instead.

When a guard denies the call — or an access gate fails — the tool call returns an error result (`isError: true`) carrying the status and detail, so the assistant sees exactly why it was refused:

```json
{
    "status": 401,
    "body": {
        "detail": "Unauthorized"
    }
}
```

Public routes (`false` in the auth map) run without guards, credentials or not.

## Options

| Option        | Default                                            | Description                                   |
| ------------- | -------------------------------------------------- | --------------------------------------------- |
| `name`        | `'MCP Server'`                                     | Human-readable name shown to AI assistants    |
| `version`     | `'1.0.0'`                                          | Semantic version string                       |
| `routeFilter` | excludes multipart, form-urlencoded, and streaming | Predicate to filter which routes become tools |
| `path`        | `'/mcp'`                                           | Mount path (Express, Fastify, and Hono)       |

## Connecting clients

After mounting the endpoint, connect your AI tools to it.

### Claude Code

```sh
claude mcp add --transport http my-api http://localhost:3000/mcp
```

### VS Code

```json
{
    "mcp.servers": {
        "my-api": {
            "command": "npx",
            "args": ["-y", "mcp-remote", "http://localhost:3000/mcp"]
        }
    }
}
```

### Cursor

```json
{
    "mcpServers": {
        "my-api": {
            "command": "npx",
            "args": ["-y", "mcp-remote", "http://localhost:3000/mcp"]
        }
    }
}
```

## Tool input structure

Tool inputs use structured keys that mirror the kizuna handler args:

```json
{
    "params": { "id": "42" },
    "query": { "page": 1, "limit": 25 },
    "body": { "name": "Alice", "email": "alice@example.com" }
}
```

Only the keys relevant to the route are present. A `GET /users/:id` route has `params` only. A `POST /users` with a body has `body` only.

## Tool responses

Every tool returns a JSON text block with the HTTP status and parsed response body:

```json
{
    "status": 200,
    "body": {
        "id": "42",
        "name": "Alice"
    }
}
```

Responses with status >= 400 set `isError: true` on the MCP result so the AI knows the call failed.

## Standalone server

If you don't want to mount on an existing app, [`createMcpServer`](/docs/reference/create-mcp-server) returns a raw `McpServer` you can connect to any transport (stdio, SSE, etc.).

```ts title="src/index.ts"
import { createMcpServer } from '@ts-kizuna/mcp';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import { api } from './api';

const server = createMcpServer(api, {
    name: 'My API',
    version: '1.0.0',
});

await server.connect(new StdioServerTransport());
```
