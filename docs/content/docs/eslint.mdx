`@ts-kizuna/eslint-plugin` catches ts-kizuna mistakes in your editor — things the type system can't express on its own, surfaced as you type instead of at runtime.

<InstallTabs packageName="@ts-kizuna/eslint-plugin" />

## Setup

Add the recommended config to your `eslint.config.js`, alongside whatever else you already run:

```js title="eslint.config.js"
import js from '@eslint/js';
import tseslint from 'typescript-eslint';
import kizuna from '@ts-kizuna/eslint-plugin';

export default [js.configs.recommended, ...tseslint.configs.recommended, kizuna.configs.recommended];
```

That's it — every rule below is now active.

## Turning a rule off

Override it after the recommended config:

```js title="eslint.config.js"
import kizuna from '@ts-kizuna/eslint-plugin';

export default [
    kizuna.configs.recommended,
    {
        rules: {
            '@ts-kizuna/no-z-coerce': 'off',
        },
    },
];
```

Or silence a single line inline:

```ts
// eslint-disable-next-line @ts-kizuna/no-z-coerce
page: z.coerce.number(),
```

## Rules

### `no-z-coerce`

Flags `z.coerce` in your schemas. kizuna already coerces query, path, and header params to their declared types ([see Coercion](/docs/building/contract#query-path-and-header-coercion)), so `z.coerce` is redundant — and `createContract` throws on it. Use the plain schema instead:

```ts
// flagged
query: z.object({
    page: z.coerce.number(),
});

// good — kizuna coerces the string for you
query: z.object({
    page: z.number(),
});
```

### `no-jsdoc-tags-in-deprecations`

Flags JSDoc inline tags — `{@link}`, `{@linkcode}`, `{@tutorial}`, and any other `{@…}` tag — inside `@deprecated` messages. kizuna serializes the text after `@deprecated` verbatim into `.kizuna/deprecations.json` and surfaces it to every generated client. Native and mobile clients can't parse JSDoc tags, so they'd show the raw `{@…}` markup. Write the message as plain text — backticks are fine:

```ts
// flagged
/**
 * @deprecated Use {@link createUser} instead.
 */

// good — plain text the clients can render
/**
 * @deprecated Use `createUser` instead.
 */
```

### `no-duplicate-deprecated`

Flags JSDoc blocks with more than one `@deprecated` tag. kizuna serializes only the **first** `@deprecated` message into `.kizuna/deprecations.json` — any later one is silently dropped and never reaches a generated client. Collapse them into a single message:

```ts
// flagged — clients only get "Use `createUser` instead."; the id warning is dropped
/**
 * @deprecated Use `createUser` instead.
 * @deprecated Numeric ids are no longer accepted.
 */

// good — one message, nothing lost
/**
 * @deprecated Use `createUser` instead. Numeric ids are no longer accepted.
 */
```
