`@ts-kizuna/eslint-plugin` catches ts-kizuna mistakes in your editor — things the type system can't express on its own, surfaced as you type instead of at runtime.

<InstallTabs packageName="@ts-kizuna/eslint-plugin" />

## Setup

Add the recommended config to your `eslint.config.js`, alongside whatever else you already run:

```js title="eslint.config.js"
import js from '@eslint/js';
import tseslint from 'typescript-eslint';
import kizuna from '@ts-kizuna/eslint-plugin';

export default [js.configs.recommended, ...tseslint.configs.recommended, kizuna.configs.recommended];
```

That's it — every rule below is now active.

## Turning a rule off

Override it after the recommended config:

```js title="eslint.config.js"
import kizuna from '@ts-kizuna/eslint-plugin';

export default [
    kizuna.configs.recommended,
    {
        rules: {
            '@ts-kizuna/no-unsupported-schema': 'off',
        },
    },
];
```

Or silence a single line inline:

```ts
query: z.object({
    // eslint-disable-next-line @ts-kizuna/no-unsupported-schema
    page: z.coerce.number(),
}),
```

## `valid-jsdoc-tags`

Contract JSDoc carries exactly four tags: `@description`, `@summary`, `@example`, and `@deprecated` ([see JSDoc](/docs/jsdoc)). Anything else is ignored, so the code reads as documented while the text reaches neither the spec, the MCP tools, nor the generated clients. This rule turns that silence into an error.

### Any other tag

A tag outside the four is flagged, whether it is a typo or a real JSDoc tag:

```ts
// flagged, and `eslint --fix` renames it
/**
 * @descriptionn Create a user.
 */

// flagged: @param is a real tag, but nothing reads it on a route
/**
 * @description Create a user.
 * @param body the user to create
 */

// good
/**
 * @description Create a user.
 */
```

`--fix` renames a typo to the tag it is closest to. Other tags have no rename to apply, so you decide what to do with them.

Prose is left alone. A note above the tags is for whoever reads the code and reaches nothing kizuna generates.

### Repeated tags

kizuna keeps the **first** `@description`, `@summary`, or `@deprecated` and silently drops the rest, so a second one is documentation you think you wrote:

```ts
// flagged: the second line never reaches a client
/**
 * @description Create a user.
 * @description Emails are unique.
 */

// good
/**
 * @description Create a user. Emails are unique.
 */
```

`@example` is the exception: the parser collects every one, so repeat it to document several values.

### Empty tags

A tag with no text after it documents nothing while reading as done. A bare `@deprecated` is fine, since deprecation needs no message:

```ts
// flagged
/**
 * @description
 */
```

### Overlong `@summary`

`@summary` becomes the OpenAPI operation summary, which renders in list views and gets truncated. Past 120 characters the rule asks you to move the detail to `@description`. Set your own limit:

```js title="eslint.config.js"
export default [
    kizuna.configs.recommended,
    {
        rules: {
            '@ts-kizuna/valid-jsdoc-tags': ['error', { maxSummaryLength: 80 }],
        },
    },
];
```

The rule reads each file's own comments, so a schema imported from another module is checked where it is written rather than where it is used.

## `no-unsupported-schema`

Flags `body`, `query`, `pathParams`, `headers`, and response schemas in your routes — plus `Kizuna.model` schemas, inline or imported — that use something ts-kizuna can't support. It follows imports, so the error lands on the offending field when it's local, or on the reference when the schema comes from another file.

### `z.coerce`

kizuna already coerces query, path, and header params to their declared types ([see Coercion](/docs/building/contract#query-path-and-header-coercion)), so `z.coerce` is redundant — and `k.routes` throws on it. Use the plain schema:

```ts
// flagged
query: z.object({
    page: z.coerce.number(),
});

// good — kizuna coerces the string for you
query: z.object({
    page: z.number(),
});
```

### JSDoc tags in `@deprecated`

kizuna serializes the text after `@deprecated` verbatim and surfaces it to every generated client. Native and mobile clients can't parse JSDoc inline tags (`{@link}`, `{@linkcode}`, any `{@…}`), so they'd show the raw markup. Write plain text — backticks are fine:

```ts
// flagged
/**
 * @deprecated Use {@link createUser} instead.
 */

// good
/**
 * @deprecated Use `createUser` instead.
 */
```

### Across files

A schema is often defined elsewhere — a shared `PaginationQuery` in its own `zod`-only module that no per-file linter would ever connect to your contract. Because the rule resolves what your contract references, it catches it anyway and reports on the reference:

```ts title="pagination.ts"
import { z } from 'zod';

export const PaginationQuery = z.object({
    page: z.coerce.number(),
});
```

```ts title="routes.ts"
import { PaginationQuery } from './pagination.js';

export const users = k.routes('users', {
    listUsers: {
        method: 'GET',
        path: '/users',
        query: PaginationQuery, // flagged here — PaginationQuery uses z.coerce
        responses: {
            200: UserListSchema,
        },
    },
});
```
