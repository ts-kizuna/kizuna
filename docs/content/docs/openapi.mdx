`@ts-kizuna/openapi` generates an [OpenAPI 3.1.0](https://spec.openapis.org/oas/v3.1.0) document from your contract.

<InstallTabs packageName="@ts-kizuna/openapi" />

## `openApiPlugin`

`openApiPlugin` serves the document and an API reference UI for it. Install it and there is nothing else to wire: it generates the document from your contract, and `api.mount` serves its routes on any adapter.

```ts title="src/lib/k.ts"
import { Kizuna } from '@ts-kizuna/core';
import { openApiPlugin } from '@ts-kizuna/openapi';

export const k = new Kizuna({
    tags,
    plugins: {
        openApiDocs: openApiPlugin({
            info: {
                title: 'My API',
                version: '1.0.0',
            },
        }),
    },
});
```

That gives you three routes:

| Path            | What                                    |
| --------------- | --------------------------------------- |
| `/docs`         | the API reference UI, Scalar by default |
| `/openapi.json` | the document                            |
| `/openapi.yaml` | the same document as YAML               |

Every path is configurable, and `false` turns any of them off: `path: false` serves the document with no UI, `yamlPath: false` serves JSON only. They are [plugin routes](/docs/plugins), so they stay out of your fetch client and out of the document itself.

The routes are public. Gate them with your framework's own middleware if that is not what you want.

### Writing it to disk

```ts title="scripts/generate-openapi.ts"
import { writeFileSync } from 'fs';
import { generateOpenApi } from '@ts-kizuna/openapi';
import { contract } from '../src/contract';

const spec = generateOpenApi(contract);

writeFileSync('openapi.yaml', spec('yaml'));
```

```sh
tsx scripts/generate-openapi.ts
```

### Serving it yourself

The plugin is the batteries-included path, not the only one:

```ts title="src/index.ts"
const spec = generateOpenApi(contract);

app.get('/openapi.yaml', (_req, res) => {
    res.type('text/yaml; charset=utf-8').send(spec('yaml'));
});
```

Leave `yamlPath` off when you do, or two handlers claim the path and whichever registered first wins. Kizuna cannot catch that one for you: it sees collisions between the contract and a plugin, but a route you register on the app yourself is invisible to it.

Mixing is the useful case: `docsPath: false` lets the plugin serve the document while you render your own UI.

### Swagger instead of Scalar

```ts
openApiPlugin({
    info,
    provider: 'swagger',
});
```

Point `cdnUrl` at a self-hosted copy for air-gapped deployments or a strict CSP.

## `generateOpenApi`

`generateOpenApi` returns a renderer. Call it with `'json'` for the document object or `'yaml'` for a YAML string. Everything it needs, `info` included, comes off the contract: you declare it once on [`openApiPlugin`](#openapiplugin) in `k.ts`, and nothing here can disagree with it.

```ts
import { generateOpenApi } from '@ts-kizuna/openapi';
import { contract } from '@shared/contract';

const spec = generateOpenApi(contract);

spec('json'); // OpenApiDocument object
spec('yaml'); // YAML string
```

## Deprecation

Routes and fields marked `/** @deprecated */` get `deprecated: true` in the generated spec — no extra options here. `generateOpenApi(contract)` reads them straight off the contract, once you've added the one-time build step. See [Deprecations](/docs/deprecations) for setup.

## Options

They go on `openApiPlugin` in `k.ts`, and `generateOpenApi` reads them from there.

```ts title="src/lib/k.ts"
openApiPlugin({
    info: {
        title: 'My API',
        version: '1.0.0',
        description: 'Optional description',
    },
    servers: [
        {
            url: 'https://api.example.com',
            description: 'Production',
        },
        {
            url: 'http://localhost:3000',
            description: 'Development',
        },
    ],
    setOperationId: true,
});
```

| Option            | Default  | Description                                                                             |
| ----------------- | -------- | --------------------------------------------------------------------------------------- |
| `info`            | required | OpenAPI `info` object                                                                   |
| `servers`         | —        | Server URLs                                                                             |
| `setOperationId`  | `false`  | Set `operationId` from the route key. Use `'concatenated-path'` to include parent keys. |
| `tags`            | —        | Top-level tag definitions                                                               |
| `operationMapper` | —        | Callback to transform each operation before it is added to the spec                     |

## Security

Security comes from the contract, not from generator options. The [identities](/docs/auth) you register on `new Kizuna()` are emitted as `components.securitySchemes`, and the contract's auth map becomes each operation's `security` — with oauth2 scopes included. There is nothing to declare here, and the spec can never disagree with what the server actually enforces.

```ts
export const user = Kizuna.identity.bearer({
    context: z.object({
        userId: z.string(),
    }),
});
```

```yaml
# generated
components:
    securitySchemes:
        user:
            type: http
            scheme: bearer
paths:
    /workspace:
        get:
            security:
                - user: []
```

Routes marked `false` in the auth map get no `security` entry — they document as public, because they are. A [`custom`](/docs/reference/kizuna-identity#custom-identities) identity also emits no `security` (OpenAPI can't describe its credential), but its routes carry an `x-kizuna-guarded` extension, so protected-out-of-band stays distinct from public.

## Validation errors

Routes with a `body` or `query` schema automatically include a `400` validation error response in the generated spec. This matches the error kizuna returns when request data fails schema validation.

If a route already declares a `400` response, the automatic validation error is not added — your declaration takes precedence.
