---
title: Deprecations
description: Declare deprecations on the contract and have them reach your editor, OpenAPI, Swift, and Kotlin.
---

| Where  | Declaration                  | Type                |
| ------ | ---------------------------- | ------------------- |
| Routes | `deprecated` on the route    | `boolean \| string` |
| Fields | `.meta({ deprecated: ... })` | `boolean \| string` |

## Routes

Set `deprecated` on the route, either `true` or a migration message:

```ts title="contract/index.ts"
export const usersRoutes = k.routes('users', {
    deleteUser: {
        method: 'DELETE',
        path: '/users/:id',
        deprecated: 'use archiveUser instead',
        responses: {
            200: z.object({
                ok: z.boolean(),
            }),
        },
    },
});
```

## Fields

Fields declare it in their [Zod metadata](https://zod.dev/metadata), with the same `true | string` shape:

```ts
const UserSchema = z.object({
    id: z.string(),
    email: z.string().meta({
        deprecated: 'use email_address instead',
    }),
    email_address: z.string(),
});
```

`deprecated` is Zod's own metadata key, typed as a boolean to match JSON Schema. `@ts-kizuna/core` widens it through declaration merging to accept the message string, so the string form type-checks in any project that has kizuna installed. `false` reads as not deprecated.

## What each output emits

OpenAPI marks the operation and the field's schema with `deprecated: true` (the spec has no message field). Swift emits `@available(*, deprecated, message: "use email_address instead")` and Kotlin `@Deprecated("use email_address instead")`, so the message reaches autocomplete and compiler warnings in both mobile clients.

## Editors

The [ts-kizuna VS Code extension](/docs/vscode) strikes through deprecated routes and fields as you code and shows the migration message on hover. Other editors load the same plugin through `tsconfig.json`, covered on the same page.
