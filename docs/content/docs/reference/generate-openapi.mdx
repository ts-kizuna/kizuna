Generate an [OpenAPI 3.1.0](https://spec.openapis.org/oas/v3.1.0) document from a contract. Returns a renderer you call with `'json'` or `'yaml'`.

<InstallTabs packageName="@ts-kizuna/openapi" />

```ts
import { generateOpenApi } from '@ts-kizuna/openapi/server';
```

## Parameters

```ts
generateOpenApi(contract: Contract, overrides?: Partial<GenerateOpenApiOptions>): OpenApiRenderer
```

| Parameter   | Type                              | Description                                                     |
| ----------- | --------------------------------- | --------------------------------------------------------------- |
| `contract`  | `Contract`                        | The contract from [`k.contract`](/docs/reference/k-contract)    |
| `overrides` | `Partial<GenerateOpenApiOptions>` | Merged over the contract's options, for what only a build knows |

It lives on `@ts-kizuna/openapi/server` because it reads your deprecations file from disk. The contract-facing entry, `@ts-kizuna/openapi`, holds [`openApiPlugin`](/docs/reference/openapi-plugin) and the document types.

## Options

Options are declared on [`openApiPlugin`](/docs/reference/openapi-plugin) in `k.ts`, and `generateOpenApi` reads them off the contract, so a build step cannot write a document that differs from the one your server serves. Pass `overrides` for what only a build step knows, such as the public `servers` list.

| Option            | Type                                  | Default   | Description                                                                             |
| ----------------- | ------------------------------------- | --------- | --------------------------------------------------------------------------------------- |
| `info`            | `{ title, version, description? }`    | required  | OpenAPI `info` object                                                                   |
| `openApiVersion`  | `'3.1.0'`                             | `'3.1.0'` | OpenAPI specification version for the generated document                                |
| `servers`         | `{ url, description? }[]`             | none      | Server URLs                                                                             |
| `setOperationId`  | `boolean \| 'concatenated-path'`      | `false`   | Set `operationId` from the route key. Use `'concatenated-path'` to include parent keys. |
| `externalDocs`    | `{ url, description? }`               | none      | Top-level external documentation link                                                   |
| `operationMapper` | `(operation, route, id) => operation` | none      | Callback to transform each operation before it is added to the spec                     |

There are no security or tag options. Security is emitted from the [`auth` map](#security-emission) and the document's tag list from [`Kizuna.tags`](/docs/reference/kizuna-tags), so neither can disagree with the contract.

## Returns

An `OpenApiRenderer` function:

```ts
renderer('json'); // OpenApiDocument object
renderer('yaml'); // YAML string
```

## Example

```ts title="src/contract/k.ts"
import { Kizuna } from '@ts-kizuna/core';
import { openApiPlugin } from '@ts-kizuna/openapi';

export const k = new Kizuna({
    plugins: {
        openApi: openApiPlugin({
            info: {
                title: 'My API',
                version: '1.0.0',
            },
            servers: [
                {
                    url: 'https://api.example.com',
                    description: 'Production',
                },
            ],
            setOperationId: true,
        }),
    },
});
```

```ts
import { generateOpenApi } from '@ts-kizuna/openapi/server';
import { contract } from './contract';

const spec = generateOpenApi(contract);

app.get('/openapi.json', (_req, res) => {
    res.json(spec('json'));
});
```

## Security emission

Security is generated from the contract, not configured on the generator. Every [identity](/docs/reference/kizuna-identity) registered on [`new Kizuna()`](/docs/reference/kizuna) is emitted under `components.securitySchemes`, and every route the [`auth` map](/docs/reference/k-contract#the-auth-map) secures references those names in its `security`, with OAuth scopes where the map declares them. Public routes (`false`) get none.

With the `user` (bearer) and `member` (API key) identities and `workspace: 'member'` in the auth map, the document contains:

```yaml
components:
    securitySchemes:
        user:
            type: http
            scheme: bearer
        member:
            type: apiKey
            name: x-workspace-token
            in: header
paths:
    /workspace:
        get:
            security:
                - member: []
```

A [`custom`](/docs/reference/kizuna-identity#custom-identities) identity is the exception: OpenAPI can't describe its credential, so it emits no `securityScheme` and no `security`. Its routes instead carry an `x-kizuna-guarded` extension, keeping a protected-out-of-band route distinct from a public one.

The spec and the runtime [guards](/docs/reference/server-guard) both derive from the auth map, so documented security is enforced security.

See the [OpenAPI guide](/docs/openapi) for Scalar integration, writing specs to disk, and breaking change detection.
