---
title: BinarySchema & z.file()
description: Binary response bodies with BinarySchema, multipart upload fields with Zod's z.file().
---

Two schemas cover non-JSON bodies: kizuna's `BinarySchema` for raw bytes, and Zod's own `z.file()` for uploaded files.

```ts
import { BinarySchema } from '@ts-kizuna/core/schemas';
import { z } from 'zod';
```

**Sending or returning a blob of bytes, use `BinarySchema`. Taking a file uploaded through a form, use `z.file()`.**

| Schema         | Is                         | Use                                                       | Swift type      |
| -------------- | -------------------------- | --------------------------------------------------------- | --------------- |
| `BinarySchema` | `z.instanceof(Uint8Array)` | Binary response bodies (PDF, images) and raw binary input | `Data`          |
| `z.file()`     | Zod's file schema          | `multipart/form-data` upload fields                       | `MultipartFile` |

The split follows what each type carries. A `File` has a filename and MIME type, which is what a multipart part needs. A `Uint8Array` is bytes alone, and a Node `Buffer` satisfies it.

## BinarySchema

Use it as a response `body` and pair it with a `contentType`. It defaults to `application/octet-stream`. The body goes to the wire as raw bytes (never JSON-serialized); the OpenAPI generator emits `type: string, format: binary`, and the Swift client decodes it to `Data`.

```ts title="routes/reports.ts"
import { BinarySchema } from '@ts-kizuna/core/schemas';
import { k } from './k';

export const reportsRoutes = k.routes('reports', {
    downloadReport: {
        method: 'GET',
        path: '/reports/:id.pdf',
        responses: {
            200: {
                body: BinarySchema,
                contentType: 'application/pdf',
            },
        },
    },
});
```

The handler returns the bytes, as a `Buffer` or `Uint8Array`. The fetch client hands the body back as a `Uint8Array`. Set `Content-Disposition` as a normal response header if you want a download:

```ts title="router/reports.ts"
downloadReport: async ({ params }) => {
    const pdf = await renderReport(params.id);
    return {
        status: 200,
        body: pdf,
        headers: {
            'content-disposition': `inline; filename="report-${params.id}.pdf"`,
        },
    };
},
```

## z.file()

Use it inside a `multipart/form-data` request body for uploaded files. Zod's own checks apply, so `.mime()` and size bounds validate on the server before the handler runs:

```ts title="users.ts"
uploadAvatar: {
    method: 'POST',
    path: '/avatar',
    contentType: 'multipart/form-data',
    body: z.object({
        file: z.file().mime('image/png').max(5_000_000),
        userId: z.string(),
    }),
    responses: {
        200: z.object({
            size: z.number(),
        }),
    },
},
```

`z.instanceof(File)` is recognized the same way, without the MIME and size checks. For `Date`, `bigint`, and `URL` values in bodies, see [Native types](/docs/reference/native-types).
