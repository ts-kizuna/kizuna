---
title: server.permission
description: Decide whether the caller holds one permission, once per request and only when something asks.
---

<BetaNotice>

Permissions are new and still settling. `server.permission` and what an implementation returns may change before v2, so pin your version if you depend on them.

</BetaNotice>

`server.permission(name, run)` implements one [permission](/docs/reference/kizuna-permission). `server.api` requires one implementation per declared permission, the way it requires one guard per identity.

```ts title="src/server/permissions.ts"
import { server } from './server';

export const canViewEventLog = server.permission('viewEventLog', () => db.featureFlags.enabled('event-log'));

export const canPromoteMember = server.permission('promoteMember', async () => {
    const memberIds = await db.memberships.findUserIds();
    return (target) => memberIds.has(target.id);
});
```

A permission applying to no record returns a boolean. One with `appliesTo` returns a predicate over that record, which may be async. One shape each.

## Arguments

| Property | Description                                                                                                            |
| -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `auth`   | The scheme-keyed context the guards produced. Every identity is optional, since one implementation serves every route. |
| `params` | The matched route's path params.                                                                                       |
| adapter  | The adapter's own context: `req`/`res` on Express, `c` on Hono, and so on.                                             |

## It runs once, and only when asked

At most once per request, on first use, and not at all when nothing asks. A route gated on `viewEventLog` never runs the `promoteMember` implementation, and two `can.promoteMember(...)` calls in one handler resolve it once.

That is why the grant set belongs in the body. Loading it there makes the predicate a set test rather than a query per record, so checking fifty records costs one query.

## It returns an answer, not a response

There is no `deny`. A route gate answers `403` with Problem Details on its own; a handler wanting its own wording declares `403` and uses `can` plus `throwError`. See [Permissions](/docs/permissions#denials).
