---
title: createServerAction
description: Turn a typed client method into a React Server Action you use like the client.
---

`createServerAction` (from `@ts-kizuna/next`) wraps a `@ts-kizuna/fetch` client method as a React Server Action. You use it **exactly like the client**: call it with the route's arguments and get back the same `{ status, body }` response, narrowed on `status`. The action runs server-side, strips the inputs a caller shouldn't supply, and runs `onSuccess` after a 2xx.

Export it from a `'use server'` module:

```ts
// src/app/users/actions.ts
'use server';
import { revalidatePath } from 'next/cache';
import { createServerAction } from '@ts-kizuna/next';
import { client } from '@/lib/api-client';

export const createUser = createServerAction(client.users.createUser, {
    onSuccess: () => {
        revalidatePath('/users');
    },
});
```

Call it and narrow on `status`:

```ts
const result = await createUser({
    body: {
        name: 'Ada',
        email: 'ada@example.com',
    },
});

if (result.status === 201) {
    result.body.id; // typed success body
} else if (result.status === 400) {
    result.body.errors; // validation issues, typed
}
```

## Result

The action returns the client method's response **unchanged** — the same `{ status, body }` (with `headers`) discriminated union you'd get from the client. Narrow on `status` for the body; multiple success statuses (`200` and `201`) each keep their own typed body.

```ts
const result = await archiveUser({ params: { id } });
if (result.status === 200) {
    result.body.alreadyArchived;
} else if (result.status === 201) {
    result.body.archivedAt;
}
```

For a `400`, `result.body` is kizuna's `ValidationError` with field-level Zod issues:

```ts
if (result.status === 400) {
    for (const issue of result.body.errors) {
        // issue.path → ['email'], issue.code → 'invalid_format', issue.message → 'Invalid email'
    }
}
```

When a route declares its **own** `400` alongside validation, `status === 400` carries both shapes; [`isValidationError`](/docs/reference/is-validation-error) (re-exported from `@ts-kizuna/next`) narrows `result.body` to just the validation shape. A genuine transport failure (the API is unreachable) throws; catch it or let a Next.js error boundary handle it.

## Options

| Option      | Default | Description                                                                                                        |
| ----------- | ------- | ------------------------------------------------------------------------------------------------------------------ |
| `inject`    | —       | Supply server-derived parts of the request; the fields are merged in and **removed from the caller's input type**. |
| `onSuccess` | —       | Run after a 2xx response — revalidate, redirect, or other side effects; receives the success response.             |

### `inject`

For values that must come from the server (an owner id, a tenant id), not the client. The returned fields are deep-merged into the request and removed from the action's argument type, so the caller can't pass or forge them:

```ts
export const createPost = createServerAction(client.posts.createPost, {
    inject: async () => ({
        body: {
            authorId: await currentUserId(),
        },
    }),
});

// the caller only knows about `title`
await createPost({
    body: {
        title,
    },
});
```

### `onSuccess`

Runs after a 2xx response with the success response — the place to revalidate, redirect, or run other effects. A throw (as `redirect` does) propagates.
