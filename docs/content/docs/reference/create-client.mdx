Create a fully typed HTTP client from a contract. The returned client mirrors the shape of the contract — each route becomes a function that accepts typed arguments and returns a typed response.

<InstallTabs packageName="@ts-kizuna/fetch" />

```ts
import { createClient } from '@ts-kizuna/fetch';
```

## Parameters

```ts
createClient(contract: Contract, config: ClientConfig): Client<Contract>
```

| Parameter  | Type           | Description                                                                   |
| ---------- | -------------- | ----------------------------------------------------------------------------- |
| `contract` | `Contract`     | The contract created with [`createContract`](/docs/reference/create-contract) |
| `config`   | `ClientConfig` | Client configuration                                                          |

## `ClientConfig`

| Option        | Type                     | Required | Description                                                               |
| ------------- | ------------------------ | -------- | ------------------------------------------------------------------------- |
| `baseUrl`     | `string`                 | Yes      | Base URL prepended to every route path                                    |
| `baseHeaders` | `Record<string, string>` | No       | Headers merged into every request                                         |
| `credentials` | `RequestCredentials`     | No       | Passed as `credentials` to every `fetch` call                             |
| `fetch`       | `typeof fetch`           | No       | Custom fetch implementation (e.g. for testing or a polyfill)              |
| `onRequest`   | `(context) => void`      | No       | Callback before each request — receives `{ url, method, headers, route }` |

## Returns

A `Client<T>` that mirrors the contract structure. Each route becomes a function accepting `{ params?, query?, body?, headers?, fetchOptions? }` and returning a `Promise` resolving to `{ status, body, headers }`.

The response is a discriminated union over the route's declared status codes. Narrow on `status` to access the correctly typed `body`.

## Example

```ts
import { createClient } from '@ts-kizuna/fetch';
import { contract } from '@shared/contract';

const client = createClient(contract, {
    baseUrl: 'http://localhost:3000',
    baseHeaders: {
        Authorization: `Bearer ${token}`,
    },
});

const result = await client.createUser({
    body: {
        name: 'Alice',
        email: 'alice@example.com',
    },
});

if (result.status === 201) {
    console.log(result.body.id);
} else {
    console.error(result.body.detail);
}
```

## Per-request options

Pass `fetchOptions` to customize individual requests:

```ts
const { body } = await client.listUsers({
    query: {
        page: 1,
    },
    fetchOptions: {
        signal: AbortSignal.timeout(5000),
    },
});
```

See the [Fetch client guide](/docs/clients/fetch) for per-request headers, validation errors, and response type narrowing.
