Create a fully typed HTTP client from a contract. The returned client mirrors the route structure — each route becomes a function that accepts typed arguments and returns a typed response.

<InstallTabs packageName="@ts-kizuna/fetch" />

```ts
import { createClient } from '@ts-kizuna/fetch';
```

## Parameters

```ts
createClient(contract: Contract, config: ClientConfig): Client
```

| Parameter  | Type           | Description                                              |
| ---------- | -------------- | -------------------------------------------------------- |
| `contract` | `Contract`     | The contract from [`k.contract`](/docs/reference/kizuna) |
| `config`   | `ClientConfig` | Client configuration                                     |

## `ClientConfig`

| Option           | Type                      | Required | Description                                                                                                              |
| ---------------- | ------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------ |
| `baseUrl`        | `string`                  | Yes      | Base URL prepended to every route path                                                                                   |
| `baseHeaders`    | `Record<string, string>`  | No       | Headers merged into every request                                                                                        |
| `credentials`    | `RequestCredentials`      | No       | Passed as `credentials` to every `fetch` call                                                                            |
| `fetch`          | `typeof fetch`            | No       | Custom fetch implementation (e.g. for testing or a polyfill)                                                             |
| `onRequest`      | `(context) => void`       | No       | Callback before each request — receives `{ url, method, headers, route }`                                                |
| `requestContext` | `Record<string, string>`  | \*       | Header values for the contract's [request context](/docs/reference/create-request-context) — required when any header is |
| `auth`           | `Record<string, () => …>` | No       | Optional credential providers per [identity](/docs/auth); the client attaches each per route                             |

## Returns

`createClient` returns the `Client`, mirroring the contract's route groups. Each route becomes a function accepting `{ params?, query?, body?, headers?, fetchOptions? }` and returning a `Promise` resolving to `{ status, body, headers }`.

`params` is typed from the route's `pathParams` schema output when one is declared (matching the server-side handler), otherwise from the `:param` placeholders in the path.

The response is a discriminated union over the route's declared status codes. Narrow on `status` to access the correctly typed `body`.

## Example

When the contract secures routes with [identities](/docs/auth), register credential providers under `auth`; the client attaches each route's credential automatically. Providers are optional — supply the ones this client holds:

```ts
import { createClient } from '@ts-kizuna/fetch';
import { contract } from './contract';

const apiClient = createClient(contract, {
    baseUrl: 'http://localhost:3000',
    auth: {
        user: () => getSessionToken(),
    },
});

const result = await apiClient.users.createUser({
    body: {
        name: 'Alice',
        email: 'alice@example.com',
    },
});

if (result.status === 201) {
    console.log(result.body.id);
} else {
    console.error(result.body.detail);
}
```

## Per-request options

Pass `fetchOptions` to customize individual requests:

```ts
const { body } = await client.users.listUsers({
    query: {
        page: 1,
    },
    fetchOptions: {
        signal: AbortSignal.timeout(5000),
    },
});
```

See the [Fetch client guide](/docs/clients/fetch) for per-request headers, validation errors, and response type narrowing.
