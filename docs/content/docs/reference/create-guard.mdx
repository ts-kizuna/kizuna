title: createGuard
description: Implement an identity's authentication check — resolve the extracted credential into typed context, or deny.

`createGuard` implements one [identity](/docs/reference/create-identity): it turns the extracted credential into the typed context handlers receive, or denies the request. One guard per identity — the [auth map](/docs/reference/kizuna#the-auth-map) decides which routes it protects.

<AdapterTabs functionName="createGuard" />

## Parameters

```ts
createGuard(contract: Contract, identity: string, run: GuardFn): Guard
```

| Parameter  | Type       | Description                                                                       |
| ---------- | ---------- | --------------------------------------------------------------------------------- |
| `contract` | `Contract` | The contract from [`k.contract`](/docs/reference/kizuna)                          |
| `identity` | `string`   | The name of an identity registered on `kizuna` — TypeScript completes it          |
| `run`      | `GuardFn`  | The check — receives the extracted credential, returns context or a `deny` result |

## How it works

The credential arrives already parsed and typed. Return the identity's context — handlers receive it under `auth`, keyed by the identity's name — or `deny(status, detail)`:

```ts title="src/lib/server.ts"
import { createGuard } from '@ts-kizuna/express';
import { contract } from './contract';

export const requireUser = createGuard(contract, 'user', ({ bearer, deny }) => {
    const session = bearer ? sessions.get(bearer.token) : undefined;
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    return {
        userId: session.userId,
    };
});
```

The return is checked against the identity's `context` and `access` schemas.

## Guard arguments

| Property                                                   | Description                                                                                     |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `bearer` / `apiKey` / `basic` / `oauth2` / `openIdConnect` | The extracted credential, keyed by the identity's method. `null` when the request carried none. |
| `params`                                                   | The matched route's path params — for guards that check access to the resource in the URL       |
| `deny`                                                     | `(status, detail) => GuardDenial` — reject with a Problem Details response                      |
| `scopes`                                                   | The matched route's required OAuth scopes (`string[]`, empty for non-scoped routes)             |
| `gatedFields`                                              | The `access` fields the matched route gates (`string[]`) — resolve expensive fields on demand   |
| framework context                                          | The adapter's native request objects — see below                                                |

The credential key matches the identity's builder, so a `createIdentity.bearer` guard destructures `{ bearer }` and a `createIdentity.apiKey` guard destructures `{ apiKey }`:

| Identity method | Credential shape                                       |
| --------------- | ------------------------------------------------------ |
| `bearer`        | `{ token: string }`                                    |
| `oauth2`        | `{ token: string }`                                    |
| `openIdConnect` | `{ token: string }`                                    |
| `basic`         | `{ username: string; password: string }`               |
| `apiKey`        | `{ in: 'header' \| 'query' \| 'cookie'; name; value }` |

## Route params

The URL usually names the resource being accessed. Take a route with `path: '/workspaces/:workspaceId/members'` and a request for:

```
GET /workspaces/ws_42/members
```

The guard receives the matched path values as `params` — here `params.workspaceId` is `'ws_42'`. A valid token isn't enough for this request: the caller must also be a member of workspace `ws_42` specifically, so the guard checks the membership against the workspace in the URL:

```ts
export const requireMember = createGuard(contract, 'member', async ({ bearer, params, deny }) => {
    const session = bearer && (await verifySession(bearer.token));
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    const membership = await findMembership(session.userId, params.workspaceId);
    if (!membership) {
        return deny(403, 'Forbidden');
    }
    return membership;
});
```

`params` is typed from the contract: its keys are the param names of the routes this identity secures, each `string | undefined` since one guard runs across all of them.

## Returning context and access

The guard returns the identity's `context` fields, plus its `access` fields when the identity declares an `access` schema:

```ts
export const requireMember = createGuard(contract, 'member', ({ apiKey, deny }) => {
    const membership = apiKey ? memberships.get(apiKey.value) : undefined;
    if (!membership) {
        return deny(403, 'Forbidden');
    }
    return membership;
});
```

Gated routes (`{ member: { role: 'owner' } }`) need no changes here — kizuna checks the returned fields against the gate and responds `403` itself.

### Resolving a field only when it's gated

When an `access` field is expensive to resolve, mark it `.optional()` and resolve it only on routes that gate it. `gatedFields` holds the fields the matched route constrains, so the guard skips the work everywhere else:

```ts
export const requireMember = createGuard(contract, 'member', async ({ apiKey, gatedFields, deny }) => {
    const membership = apiKey ? await findMembership(apiKey.value) : undefined;
    if (!membership) {
        return deny(403, 'Forbidden');
    }
    if (gatedFields.includes('permissions')) {
        return { ...membership, permissions: await loadPermissions(membership.id) };
    }
    return membership;
});
```

kizuna still enforces the gate on the returned value — `gatedFields` only tells the guard what to resolve. A guard that omits a gated field is denied `403`.

An [authentication-only identity](/docs/reference/create-identity#authentication-only-identities) has no `context` or `access`, so its guard returns nothing on success — no `return {}` boilerplate — or `deny(...)` to reject:

```ts
export const requireApiKey = createGuard(contract, 'apiConsumer', async ({ apiKey, deny }) => {
    if (!apiKey || !(await isKnownKey(apiKey.value))) {
        return deny(401, 'Unauthorized');
    }
});
```

## Framework context

The credential, `deny`, `scopes`, and `gatedFields` arguments are the same everywhere; each adapter adds its native request objects:

| Adapter | Context            |
| ------- | ------------------ |
| Express | `req`, `res`       |
| Hono    | `c`                |
| Fastify | `request`, `reply` |
| Next.js | `request`          |

```ts
export const requireUser = createGuard(contract, 'user', async ({ bearer, req, deny }) => {
    const session = bearer && (await verifySession(bearer.token));
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    console.log(`[auth] ${req.method} ${req.path} as ${session.userId}`);
    return {
        userId: session.userId,
    };
});
```

## OAuth scopes

For `oauth2` identities, the guard receives the matched route's scopes from the auth map (`{ user: ['users:write'] }`):

```ts
export const requireUser = createGuard(contract, 'user', async ({ oauth2, scopes, deny }) => {
    const claims = oauth2 && (await verifyToken(oauth2.token));
    if (!claims) {
        return deny(401, 'Unauthorized');
    }
    if (!scopes.every((scope) => claims.scopes.includes(scope))) {
        return deny(403, 'Insufficient scope');
    }
    return {
        userId: claims.sub,
    };
});
```

## Registering guards

Pass the guards to [`createApi`](/docs/reference/create-api), keyed by identity name:

```ts
import { createApi } from '@ts-kizuna/express';
import { contract } from './contract';
import { router, requireUser, requireMember } from './lib/server';

export const api = createApi({
    contract,
    router,
    guards: {
        user: requireUser,
        member: requireMember,
    },
});
```

The same guards protect [MCP tool calls](/docs/reference/create-mcp-endpoint).

## `deny` and `ProblemDetailsSchema`

`deny(status, detail)` writes an [RFC 9457 Problem Details](/docs/reference/problem-details-schema) body:

```json
{
    "type": "about:blank",
    "title": "Unauthorized",
    "status": 401,
    "detail": "Unauthorized"
}
```

Declare the status codes with `ProblemDetailsSchema` so they appear in the contract and the spec:

```ts
import { ProblemDetailsSchema } from '@ts-kizuna/core/schemas';
import { k } from './k';

const usersRoutes = k.routes('users', {
    getUser: {
        method: 'GET',
        path: '/users/:id',
        responses: {
            200: UserSchema,
            401: ProblemDetailsSchema,
            403: ProblemDetailsSchema,
            404: ProblemDetailsSchema,
        },
    },
});
```
