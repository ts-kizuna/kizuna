`createGuard` turns an access check into a piece of adapter middleware. It handles the boilerplate of error responses and continuing the chain — you just write the check.

<AdapterTabs functionName="createGuard" />

## How it works

A guard receives the framework's request context and a `deny` function. Call `deny(status, detail)` to reject the request with an [RFC 9457 Problem Details](/docs/reference/problem-details-schema) response. Return without calling `deny` to allow the request through.

No `next()` calls. No manual `res.json()` or `c.json()`. Just check, then deny or continue. To pass data to handlers, attach it to the native request or context — guards run before the handler, so whatever they set is available downstream.

## Hono

```ts
import { createGuard } from '@ts-kizuna/hono';

type AuthEnv = {
    Variables: {
        user: {
            id: string;
            role: string;
        };
    };
};

const requireAdmin = createGuard<AuthEnv>(async ({ c, deny }) => {
    const user = c.get('user');
    if (user.role !== 'admin') {
        return deny(403, 'Forbidden');
    }
});
```

The `Env` type parameter follows Hono's convention for typed context variables.

### Resolving entities

Guards are ideal for multi-tenant apps where you resolve an entity and check membership before the handler runs, then stash it on the context:

```ts
const requireMembership = createGuard<AuthEnv>(async ({ c, deny }) => {
    const user = c.get('user');
    const workspaceId = c.req.param('id');
    if (!workspaceId) {
        return deny(400, 'Missing workspace id');
    }

    const membership = await checkMembership(user.id, workspaceId);
    if (!membership) {
        return deny(403, 'Forbidden');
    }

    c.set('member', membership);
});
```

## Express

```ts
import { createGuard } from '@ts-kizuna/express';

const requireUser = createGuard(({ req, deny }) => {
    const session = sessions.get(bearerToken(req) ?? '');
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    req.userId = session.userId;
});
```

Type your request properties with [declaration merging](/docs/adapters/express#type-safe-request-properties) so `req.userId` is typed in guards and handlers alike.

## Next.js

```ts
import { createGuard } from '@ts-kizuna/next';

const requireUser = createGuard(({ request, route, deny }) => {
    const auth = request.headers.get('authorization');
    const session = sessions.get(bearerToken(auth) ?? '');
    if (!session) {
        return deny(401, 'Unauthorized');
    }
    (request as AuthedRequest).userId = session.userId;
});
```

The `route` parameter holds the matched route's `path` and `method`, useful for per-route decisions inside a shared guard. Type your request properties with [module augmentation](/docs/adapters/next#type-safe-request-properties).

## Wiring guards to routes

A guard returns adapter middleware, so it plugs straight into [`createMiddleware`](/docs/reference/create-middleware) (or the inline `middleware` map on [`createApi`](/docs/reference/create-api)):

```ts
import { createMiddleware } from '@ts-kizuna/hono';
import { contract } from './contract';

const middleware = createMiddleware(contract, {
    users: [authenticate, requireAdmin],
    members: [authenticate, requireMembership],
    health: [],
});
```

## `deny` and `ProblemDetailsSchema`

`deny(status, detail)` writes an [RFC 9457 Problem Details](/docs/reference/problem-details-schema) body — the same shape as kizuna's built-in errors (404, 400 validation, 405):

```json
{
    "type": "about:blank",
    "title": "Forbidden",
    "status": 403,
    "detail": "Forbidden"
}
```

Declare these status codes with `ProblemDetailsSchema` so they appear in the contract and the generated spec:

```ts
import { ProblemDetailsSchema } from '@ts-kizuna/core/schemas';
import { k } from './k';

const usersRoutes = k.routes('users', {
    getUser: {
        method: 'GET',
        path: '/users/:id',
        responses: {
            200: UserSchema,
            401: ProblemDetailsSchema,
            403: ProblemDetailsSchema,
            404: ProblemDetailsSchema,
        },
    },
});
```

The routes, the guards, and kizuna's built-in errors all produce the same shape.
