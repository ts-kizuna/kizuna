`new Kizuna()` creates one API surface. Keep the instance as `k`, then use `k.routes` to define route groups and `k.contract` to assemble them.

<InstallTabs packageName="@ts-kizuna/core" />

```ts
import { Kizuna } from '@ts-kizuna/core';
```

## Parameters

```ts
new Kizuna(config?: {
    identities?: Record<string, SecurityScheme>;
    requestContext?: Record<string, RequestContext>;
    tags?: TagSet;
    plugins?: Record<string, ContractPlugin>;
    settings?: {
        validation?: { issueCodes?: readonly string[] };
        jobs?: JobsConfig;
    };
}): K
```

What the surface declares sits at the top level. How it behaves sits under `settings`.

| Field                            | Type                             | Description                                                                                                                                                     |
| -------------------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `identities`                     | `Record<string, SecurityScheme>` | Optional. The API's identities from the [`Kizuna.identity` builders](/docs/reference/kizuna-identity). The keys become the names the `auth` map and guards use. |
| `requestContext`                 | `Record<string, RequestContext>` | Optional. Declarations from [`Kizuna.requestContext`](/docs/reference/kizuna-request-context), the request-scoped values every handler receives.                |
| `tags`                           | `TagSet`                         | Optional. A tag set from [`Kizuna.tags`](/docs/reference/kizuna-tags). Its keys become the allowed group tags.                                                  |
| `plugins`                        | `Record<string, ContractPlugin>` | Optional. The plugins this API declares. Their keys become the names `server.api` and handlers use. See [Plugins](/docs/plugins).                               |
| `settings.validation.issueCodes` | `readonly string[]`              | Optional. Custom validation issue codes this API's handlers may emit via `k.issue`. Captured as a literal union.                                                |
| `settings.jobs`                  | `JobsConfig`                     | Optional. Settings shared by every job. The jobs themselves are declared with `k.jobs`. See [Jobs](/docs/jobs).                                                 |

### `JobsConfig`

Settings shared by every job. The jobs themselves are declared with [`k.jobs`](/docs/reference/k-jobs).

| Field      | Default   | Description                                                                        |
| ---------- | --------- | ---------------------------------------------------------------------------------- |
| `path`     | `'/jobs'` | The namespace both job endpoints are mounted under. Nothing is served on it itself |
| `method`   | `'POST'`  | `'GET'` instead, for schedulers that only send `GET`, such as Vercel Cron          |
| `windowMs` | `60000`   | How far back a tick looks for due jobs. Widen it when the scheduler delivers late  |
| `only`     | none      | Dispatch only these jobs                                                           |
| `exclude`  | none      | Never dispatch these                                                               |

## Returns

The instance, the authoring surface for this API:

| Method       | Signature                              | Description                                                  |
| ------------ | -------------------------------------- | ------------------------------------------------------------ |
| `k.routes`   | `(tag, defs) => Routes`                | Define a route group under one of the tag set's keys.        |
| `k.auth`     | `(routes, map) => AuthMap`             | Build the auth map, typed against the routes and identities. |
| `k.jobs`     | `(identity, definitions) => Jobs`      | Declare scheduled jobs and the identity they require.        |
| `k.contract` | `({ routes, jobs, auth }) => Contract` | Assemble route groups into the contract shared everywhere.   |
| `k.issue`    | `(ctx, issue) => void`                 | Raise a typed validation issue code inside a Zod refinement. |

## Example

Construct it once, usually in a `k.ts` file, then import `k` wherever you define routes.

```ts
// k.ts
import { Kizuna } from '@ts-kizuna/core';
import { tags } from './tags';
import { user, member } from './identities';
import { analytics } from './request-contexts';

export const k = new Kizuna({
    identities: {
        user,
        member,
    },
    requestContext: {
        analytics,
    },
    tags,
    settings: {
        validation: {
            issueCodes: ['invalid_phone_number'],
        },
    },
});
```

## Request context

`requestContext` registers declarations from [`Kizuna.requestContext`](/docs/reference/kizuna-request-context), the request-scoped values like analytics ids or a logger. Every handler receives them typed under `requestContext`, keyed by their name; each is resolved per request by a [`server.requestContext`](/docs/reference/server-request-context) resolver wired on `server.api`.

```ts title="src/contract/request-contexts.ts"
import { z } from 'zod';
import { Kizuna } from '@ts-kizuna/core';

export const analytics = Kizuna.requestContext(
    z.object({
        sessionId: z.string().nullable(),
    })
);
```

```ts title="src/contract/k.ts"
import { analytics } from './request-contexts';

export const k = new Kizuna({
    requestContext: {
        analytics,
    },
});
```

```ts
listUsers: ({ query, requestContext }) => {
    track(requestContext.analytics.sessionId, 'listUsers');
    // ...
},
```
