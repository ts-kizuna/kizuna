title: ErrorResponse
description: Standard error response schema used across kizuna.
---

The standard error response shape used by kizuna. Matches the format produced by [`deny()`](/docs/reference/create-guard#deny-and-errorresponse) in guards, validation errors, and all built-in error responses (404, 405, 415, etc.).

```ts
import { ErrorResponse } from '@ts-kizuna/core';
```

## Shape

```json
{
    "message": "string"
}
```

## Usage in contracts

Use `ErrorResponse` in your contract's `responses` to document error status codes:

```ts
import { createContract } from '@ts-kizuna/core';
import { ErrorResponse } from '@ts-kizuna/core';

const contract = createContract({
    getUser: {
        method: 'GET',
        path: '/users/:id',
        responses: {
            200: UserSchema,
            401: ErrorResponse,
            403: ErrorResponse,
            404: ErrorResponse,
        },
    },
    createUser: {
        method: 'POST',
        path: '/users',
        body: CreateUserSchema,
        responses: {
            201: UserSchema,
            400: ErrorResponse,
        },
    },
});
```

## What produces it

Everything in kizuna that returns a non-success response uses this shape:

| Source                 | Example                             |
| ---------------------- | ----------------------------------- |
| Guards (`deny`)        | `deny(403, 'Forbidden')`            |
| Validation errors      | Invalid body, query, or path params |
| Route not found        | 404 for unmatched paths             |
| Method not allowed     | 405 with `Allow` header             |
| Unsupported media type | 415 for wrong `Content-Type`        |
| Handler errors         | 500 for unhandled exceptions        |

## OpenAPI

`ErrorResponse` is a named model — it appears as `ErrorResponse` in the generated OpenAPI spec under `components/schemas`, keeping your API documentation clean and consistent.
