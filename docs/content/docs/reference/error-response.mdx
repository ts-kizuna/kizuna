title: ErrorResponse
description: RFC 9457 Problem Details error response schema used across kizuna.
---

The standard [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457) error response shape used by kizuna. Matches the format produced by [`deny()`](/docs/reference/create-guard#deny-and-errorresponse) in guards and all built-in error responses (404, 405, 415, etc.).

```ts
import { ErrorResponse } from '@ts-kizuna/core/schemas';
```

## Shape

```json
{
    "type": "about:blank",
    "title": "Not Found",
    "status": 404,
    "detail": "User not found"
}
```

| Field    | Description                                                                             |
| -------- | --------------------------------------------------------------------------------------- |
| `type`   | Problem type URI. `about:blank` means "no additional semantics beyond the status code." |
| `title`  | Short human-readable summary matching the HTTP status phrase.                           |
| `status` | HTTP status code.                                                                       |
| `detail` | Human-readable explanation specific to this occurrence.                                 |

## Usage in contracts

Use `ErrorResponse` in your contract's `responses` to document error status codes:

```ts
import { createContract } from '@ts-kizuna/core';
import { ErrorResponse } from '@ts-kizuna/core/schemas';

const contract = createContract({
    getUser: {
        method: 'GET',
        path: '/users/:id',
        responses: {
            200: UserSchema,
            401: ErrorResponse,
            403: ErrorResponse,
            404: ErrorResponse,
        },
    },
});
```

## Usage in handlers

Handlers only need to provide `detail` — kizuna fills in `type`, `title`, and `status` automatically:

```ts
const router = createRouter(contract, {
    getUser: ({ params, error }) => {
        const user = users.get(params.id);
        if (!user) {
            return error({
                status: 404,
                body: {
                    detail: 'User not found',
                },
            });
        }
        return {
            status: 200,
            body: user,
        };
    },
});
```

The response sent to the client includes the full RFC 9457 envelope:

```json
{
    "type": "about:blank",
    "title": "Not Found",
    "status": 404,
    "detail": "User not found"
}
```

## What produces it

Everything in kizuna that returns a non-success response uses this shape:

| Source                 | Example                      |
| ---------------------- | ---------------------------- |
| Guards (`deny`)        | `deny(403, 'Forbidden')`     |
| Route not found        | 404 for unmatched paths      |
| Method not allowed     | 405 with `Allow` header      |
| Unsupported media type | 415 for wrong `Content-Type` |
| Handler errors         | 500 for unhandled exceptions |

All built-in error responses use `application/problem+json` as the content type.

## OpenAPI

`ErrorResponse` is a named model — it appears as `ErrorResponse` in the generated OpenAPI spec under `components/schemas`, keeping your API documentation clean and consistent.
