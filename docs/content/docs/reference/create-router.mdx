title: createRouter

Bind handler implementations to a contract. The router mirrors the contract's route groups; each handler receives validated inputs and must return a response matching the route's declared status codes.

<AdapterTabs functionName="createRouter" />

## Parameters

```ts
createRouter(contract: Contract, router: Router<Contract>): Router<Contract>
createRouter(contract: Contract, group: string, handlers: Router<Contract>[Group]): Router<Contract>[Group]
```

| Parameter  | Type               | Description                                                         |
| ---------- | ------------------ | ------------------------------------------------------------------- |
| `contract` | `Contract`         | The contract from [`k.contract`](/docs/reference/kizuna)            |
| `group`    | `string`           | Optional. A route group key, to implement one group in its own file |
| `router`   | `Router<Contract>` | One handler function per route, grouped like the routes             |

## Returns

The router, type-checked against the contract. Pass it to [`createApi`](/docs/reference/create-api).

## Example

```ts title="src/lib/router.ts"
import { createRouter } from '@ts-kizuna/express';
import { contract } from './contract';

export const router = createRouter(contract, {
    users: {
        listUsers: async ({ query }) => {
            const found = await db.users.findMany({
                skip: (query.page - 1) * query.limit,
                take: query.limit,
            });
            return {
                status: 200,
                body: {
                    users: found,
                    total: await db.users.count(),
                },
            };
        },
        getUser: async ({ params }) => {
            const user = await db.users.findById(params.id);
            if (!user) {
                return {
                    status: 404,
                    body: {
                        detail: 'User not found',
                    },
                };
            }
            return {
                status: 200,
                body: user,
            };
        },
    },
});
```

Pass the router to [`createApi`](/docs/reference/create-api):

```ts
export const api = createApi({
    contract,
    router,
});
```

## Implementing one group at a time

Pass a group key as the second argument to type a single group's handlers — handy when each group lives in its own file:

```ts title="src/lib/users-handlers.ts"
import { createRouter } from '@ts-kizuna/express';
import { contract } from './contract';

export const usersHandlers = createRouter(contract, 'users', {
    listUsers: ({ query }) => {
        // ...
    },
    getUser: ({ params }) => {
        // ...
    },
});
```

Assemble the groups into the full router afterwards:

```ts
export const router = createRouter(contract, {
    users: usersHandlers,
    health: healthHandlers,
});
```

## Handler arguments

Each handler receives an object with the validated inputs for that route:

| Property  | Available when                       |
| --------- | ------------------------------------ |
| `params`  | Route path has `:param` placeholders |
| `query`   | Route has a `query` schema           |
| `body`    | Route has a `body` schema            |
| `headers` | Route has a `headers` schema         |
| `error`   | Always                               |

Secured routes additionally receive each required identity's context, under the identity's name — see below.

## Identity context

Routes the contract's [`auth` map](/docs/reference/kizuna#the-auth-map) secures receive the [guard's](/docs/reference/create-guard) return value in their handler args, keyed by the identity's name. No request mutation, no casts — the type flows from the identity's schemas:

```ts
members: {
    listMembers: ({ user }) => ({
        status: 200,
        body: {
            members: findMembersExcept(user.userId),
        },
    }),
},
```

When the auth map gates a route on access fields, the handler's type narrows to the gate. With `deleteWorkspace` gated to `{ member: { role: 'owner' } }`:

```ts
workspace: {
    deleteWorkspace: ({ member }) => ({
        status: 200,
        body: {
            ok: member.role === 'owner',
        },
    }),
},
```

Routes requiring multiple identities receive each one: `transfer: ({ user, member }) => ...`.

## Handler return type

Return `{ status, body }` matching one of the route's declared responses. TypeScript enforces that the status code and body type match. For routes with typed response headers, include `headers` too.

## Adapter-specific context

Each adapter adds framework-specific properties to the handler arguments:

| Adapter | Extra properties   | Description                       |
| ------- | ------------------ | --------------------------------- |
| Express | `req`, `res`       | Native Express request / response |
| Fastify | `request`, `reply` | Fastify request / reply           |
| Hono    | `c`                | Hono context                      |
| Next.js | `request`          | `NextRequest` object              |

These are for framework-specific needs (cookies, streaming, headers not in the contract). Authentication data doesn't live here — it arrives typed through the [identity context](#identity-context).

## `RouteHandler` and `Router` types

Annotate a single handler, or the whole router at once:

```ts
import type { RouteHandler, Router } from '@ts-kizuna/express';
import { contract } from './contract';

const getUser: RouteHandler<typeof contract.routes.users.getUser> = async ({ params }) => {
    // ...
};

export const router: Router<typeof contract> = {
    // ...
};
```

`Router<typeof contract>` types the full handler tree — including each secured route's identity context from the auth map — which you pass straight to `createApi`'s `router`. Use `RouteHandler` when you split a handler out into its own file.

See the [Router guide](/docs/building/router) for validation errors, error responses, and more.
