title: createRouter
description: Bind typed handler implementations to a contract, checked against every route.

Bind handler implementations to a contract. The router mirrors the contract's route groups; each handler receives validated inputs and must return a response matching the route's declared status codes.

<AdapterTabs functionName="createRouter" />

## Parameters

```ts
createRouter(contract: Contract, router: Router<Contract>): Router<Contract>
```

| Parameter  | Type               | Description                                              |
| ---------- | ------------------ | -------------------------------------------------------- |
| `contract` | `Contract`         | The contract from [`k.contract`](/docs/reference/kizuna) |
| `router`   | `Router<Contract>` | One handler function per route, grouped like the routes  |

## Returns

The router, type-checked against the contract. Pass it to [`createApi`](/docs/reference/create-api).

## Example

```ts title="src/lib/router.ts"
import { createRouter } from '@ts-kizuna/express';
import { contract } from './contract';

export const router = createRouter(contract, {
    users: {
        listUsers: async ({ query }) => {
            const found = await db.users.findMany({
                skip: (query.page - 1) * query.limit,
                take: query.limit,
            });
            return {
                status: 200,
                body: {
                    users: found,
                    total: await db.users.count(),
                },
            };
        },
        getUser: async ({ params }) => {
            const user = await db.users.findById(params.id);
            if (!user) {
                return {
                    status: 404,
                    body: {
                        detail: 'User not found',
                    },
                };
            }
            return {
                status: 200,
                body: user,
            };
        },
    },
});
```

Pass the router to [`createApi`](/docs/reference/create-api):

```ts
export const api = createApi({
    contract,
    router,
});
```

## Handler arguments

Each handler receives an object with the validated inputs for that route:

| Property  | Available when                       |
| --------- | ------------------------------------ |
| `params`  | Route path has `:param` placeholders |
| `query`   | Route has a `query` schema           |
| `body`    | Route has a `body` schema            |
| `headers` | Route has a `headers` schema         |
| `error`   | Always                               |

## Handler return type

Return `{ status, body }` matching one of the route's declared responses. TypeScript enforces that the status code and body type match. For routes with typed response headers, include `headers` too.

## Adapter-specific context

Each adapter adds framework-specific properties to the handler arguments:

| Adapter | Extra properties   | Description                       |
| ------- | ------------------ | --------------------------------- |
| Express | `req`, `res`       | Native Express request / response |
| Fastify | `request`, `reply` | Fastify request / reply           |
| Hono    | `c`                | Hono context                      |
| Next.js | `request`          | `NextRequest` object              |

Auth middleware attaches data to the request or context (see [`createGuard`](/docs/reference/create-guard)); handlers read it from there — for example `req.userId` on Express or `c.get('user')` on Hono.

## `RouteHandler` and `Router` types

Annotate a single handler, or the whole router at once:

```ts
import type { RouteHandler, Router } from '@ts-kizuna/express';
import { contract } from './contract';

const getUser: RouteHandler<typeof contract.routes.users.getUser> = async ({ params }) => {
    // ...
};

export const router: Router<typeof contract.routes> = {
    // ...
};
```

`Router<typeof contract.routes>` types the full handler tree, which you pass straight to `createApi`'s `router`. Use `RouteHandler` when you split a handler out into its own file.

See the [Router guide](/docs/building/router) for validation errors, error responses, and more.
