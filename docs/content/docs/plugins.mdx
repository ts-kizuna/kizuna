A plugin adds endpoints, helpers your handlers can call, or both. It gets your contract, and everything it adds is typed.

## Installing one

A plugin ships as two modules. The declaration goes on `new Kizuna()`:

```ts title="src/contract/k.ts"
import { Kizuna } from '@ts-kizuna/core';
import { mcpPlugin } from '@ts-kizuna/mcp';

export const k = new Kizuna({
    tags,
    identities,
    plugins: {
        mcp: mcpPlugin({
            name: 'My API',
        }),
    },
});
```

The server half goes on `server.api`, under the same key:

```ts title="src/server/api.ts"
import { mcpPluginServer } from '@ts-kizuna/mcp/server';

export const api = server.api({
    router,
    plugins: {
        mcp: mcpPluginServer(),
    },
});
```

The key you choose is the plugin's name everywhere else, and handlers read it under `plugins.mcp`. Miss the second half and `server.api` throws, naming the module to import.

The declaration takes plain data; the contract it rides on is shared with your clients. Anything live, a store, a driver, an SDK, goes in the server half.

`api.mount` serves its routes along with yours, on every adapter.

## Using what a plugin offers

A plugin can hand your handlers functions to call, under `plugins`:

```ts title="src/server/router/index.ts"
updateUser: async ({ params, body, plugins }) => {
    const user = await db.users.update(params.id, body);
    plugins.audit.record('users.updateUser');

    return {
        status: 200,
        body: user,
    };
},
```

Plugin names come from other people, so they are namespaced under `plugins` rather than spread into the handler args, where one called `body` would shadow your request body. Destructure it for the short form:

```ts
updateUser: async ({ params, body, plugins: { audit } }) => {
```

A contract with no plugins gets no `plugins` argument at all.

## Plugin routes

A plugin's routes run through the same pipeline as yours, with the same validation, guards, access gates and problem details. They never join `contract.routes`, so they stay out of everything generated from it.

|                           | your routes | a plugin's routes |
| ------------------------- | ----------- | ----------------- |
| declared with             | `k.routes`  | the plugin        |
| served by `api.mount`     | yes         | yes               |
| validated, guarded        | yes         | yes               |
| in your fetch client      | yes         | **no**            |
| in OpenAPI, Swift, Kotlin | yes         | **no**            |

If a plugin claims a path your contract already uses, `server.api` throws and names both.
